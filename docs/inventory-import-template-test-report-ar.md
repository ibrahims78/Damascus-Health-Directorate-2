# تقرير اختبار نموذج Excel

**تاريخ التنفيذ:** 2026-09-10  
**إصدار النموذج:** `4.0`  
**بيئة الاختبار:** Node.js 20+، SheetJS، LibreOffice headless، Desktop/PGlite

## النطاق

اختُبر النموذج الذي تنشئه واجهة الإعدادات من حيث الأوراق والرؤوس والتعليمات
والقيم المرجعية والتحقق من البيانات وتنسيق التاريخ والنص.

## النتائج

| الحالة | النتيجة | الدليل |
|---|---|---|
| ورقة المواد والدفعات | ناجح | اختبار القبول يقرأ ورقتين ويدخل مادة ودفعتين |
| ورقة التعليمات | منفذ في الواجهة | الدالة تنشئ قواعد التعبئة والإصدار `4.0` |
| ورقة القيم المرجعية | منفذ في الواجهة | تنشئ التصنيفات والوحدات وتستخدمها في Data Validation |
| Data Validation | ناجح بنيويًا | فحص XML يضيف قوائم التصنيف والوحدة وحدود الأعداد والتواريخ |
| الحفاظ على الأصفار البادئة | ناجح | الرمز يعالج كنص واختبار الوحدة يثبت `0007` |
| تنسيق التاريخ | ناجح بنيويًا | نمط `yyyy-mm-dd` يضاف إلى ورقة الدفعات |
| فتح وإعادة حفظ LibreOffice | ناجح | `pnpm run acceptance:inventory` حافظ على الورقتين والدفعتين |
| Excel وGoogle Sheets بواجهة رسومية | غير منفذ آليًا | يحتاج اختبار قبول يدوي ببرامج المستخدم الفعلية |

## تفاصيل التحقق

النموذج يجمّد صف الرأس، يدعم الاتجاه من اليمين إلى اليسار، ويضع المرشحات حتى
الصف 1000. ورقة التعليمات تذكر:

1. إصدار النموذج.
2. أسماء الأوراق.
3. طريقة الحفاظ على الأصفار البادئة.
4. صيغ التاريخ المقبولة.
5. منع تغيير رصيد المادة الموجودة من ورقة التعريفات.
6. استخدام ورقة الدفعات لإضافة أكثر من دفعة.

## القرار

النموذج **مقبول آليًا للمسار الحالي**. يبقى اعتماد Excel المكتبي وGoogle Sheets
اختبارًا تشغيليًا يدويًا، ولا يُعتبر فشلًا برمجيًا ما لم يظهر تلف أو تغير في
الرؤوس أو التواريخ أو الرموز.
