# دليل التشغيل التجريبي — المزامنة والنسخ

هذا الدليل إلزامي قبل قرار Go/No-Go. التشغيل التجريبي لا يستخدم بيانات الإنتاج
مباشرة، ولا يسمح بتجاوز بوابة النسخ الاحتياطي أو مراجعة التعارضات.

## قبل البدء

1. اختيار عقدة Web وعقدة Windows وعقدة Android بأسماء واضحة.
2. تغيير كلمة مرور المسؤول الافتراضية وتخزين كلمات مرور الحزم في مدير أسرار
   خارجي، وليس في Git أو سجل التدقيق.
3. أخذ Full Backup والتحقق منه ثم تسجيل `packageHash` في تقرير الـPilot.
4. تشغيل `pnpm --filter @workspace/scripts phase7:sync` و
   `pnpm --filter @workspace/scripts phase8:relay` و
   `pnpm --filter @workspace/scripts phase9:conflicts`.
5. إنشاء رمز Pairing لكل عقدة، تسجيل `nodeId`، ثم إلغاء الرمز بعد الاستهلاك.

## الدورة اليومية

- تسجيل تغييرات كل عقدة قبل بدء العمل.
- إنشاء Delta Sync من العقدة المصدر، والتحقق من الـmanifest والوجهة.
- عند عدم توفر اتصال مباشر، رفع ملف `.dme-sync` المشفر إلى Relay أو نقله USB.
- تنزيل الحزمة في العقدة الهدف، فحصها محلياً، ثم تطبيقها ذرياً.
- تسجيل ACK لكل اتجاه وعدم إعلان الجلسة مكتملة قبل ACK الاتجاهين.
- مراجعة طابور التعارضات في صفحة **المزامنة والعقد**؛ الحركات والرصيد لا
  تعتمد تلقائياً عند وجود تعارض حرج.

## اختبارات الفقد والاستعادة

- فقدان جهاز: إلغاء العقدة الموثوقة، أخذ نسخة قبل إعادة الاقتران، وعدم إعادة
  استخدام `nodeId` القديم.
- جهاز جديد: إنشاء هوية جديدة، pairing جديد، استعادة Full ثم Delta، ثم تقرير
  مطابقة للأرصدة والعهد والدفعات.
- فقدان الرد أو ACK: إعادة فتح الجلسة نفسها؛ لا تُنشأ عملية بديلة ولا تُحذف
  الحزمة الأصلية قبل انتهاء الاحتفاظ.
- تلف آخر نسخة: استخدام آخر نسخة ناجحة فقط بعد اجتياز `verify` وdry-run.

## مؤشرات المتابعة

سجل أسبوعياً: عدد الجلسات، الحزم المكررة، التعارضات حسب الخطورة، زمن التطبيق،
فشل التحقق، نجاح الاستعادة، ومساحة Relay. أي فقد صامت أو رصيد سالب أو حزمة
معدلة يوقف الـPilot ويحوّل القرار إلى No-Go.

## نموذج القرار

| البند | النتيجة |
|---|---|
| Full + Delta restore بدون فقد | يملأه مسؤول البيانات |
| Windows ↔ Android | يملأه مسؤول التشغيل |
| Android ↔ Web Relay | يملأه مسؤول التشغيل |
| التعارضات الحرجة | لا يوجد مفتوح قبل Go |
| مراجعة التدقيق والصلاحيات | يوقعها مسؤول النظام |
| قرار Go / No-Go | يوقعه مسؤول البيانات |
