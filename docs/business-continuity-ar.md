# استمرارية الأعمال والتعافي

## مستويات التشغيل

### فقد مؤقت للاتصال

يستمر الموقع في Desktop/PGlite، وتبقى التغييرات في outbox. لا تحذف السجل أو
تعيد تهيئة العقدة. عند عودة الاتصال نفذ مزامنة متجهة، ثم تحقق من التعارضات
والرصيد قبل متابعة الحركة.

### تعطل التطبيق أو الجهاز

1. أوقف الكتابة إن كانت الحالة غير معروفة.
2. خذ نسخة من مجلد البيانات بالطريقة المعتمدة، دون نسخ الأسرار إلى Git.
3. شغل جهازًا بديلًا أو قاعدة اختبارية.
4. افحص آخر Full Backup ثم نفذ restore في البيئة البديلة.
5. تحقق من المستخدمين محليًا؛ لا تستعيد hashes أو sessions من الحزمة.
6. وثق القرار قبل إعادة فتح الموقع.

### فساد قاعدة البيانات أو حزمة النسخ

توقف عن الاستعادة المتكررة، احتفظ بالنسخة الفاسدة للتحقيق، وانتقل إلى آخر
Full Backup سليم. لا تستخدم Delta فوق خط أساس لم يثبت سلامته.

## جدول قرار التعافي

| الحالة | الإجراء الأول | مصدر التعافي | شرط العودة |
|---|---|---|---|
| اتصال مفقود | استمرار محلي مضبوط | outbox + delta | تقارب المتجهات |
| جهاز متوقف | تشغيل بديل | آخر Full سليم | healthz وفحص الأعمال |
| migration فاشلة | إيقاف API | pre-migration أو تعويض | readiness ناجح |
| نسخة معدلة | رفض الحزمة | Full أقدم موثوق | MAC/checksum ناجح |
| فقد مفتاح | إيقاف التبادل | مفتاح بديل معتمد | إعادة اقتران وفحص |

## اختبار الاستمرارية

ينفذ مسؤول التشغيل دوريًا:

```bash
env -u DATABASE_URL BACKUP_ACCEPTANCE_PORT=8391 pnpm backup:acceptance
```

يجب حفظ نتيجة الأمر في سجل داخلي مع commit ونسخة Node وحجم الحزمة والأزمنة.
هذه fixtures صناعية ولا تثبت صلاحية تخزين الإنتاج. قبل G3 يجب تنفيذ تمرين
على نسخة منزوعة الهوية وفي بيئة تشبه موقع Pilot.

## الاتصالات والتصعيد

يجب أن يحتوي سجل الحادثة على مالك تشغيل وبديل ومسؤول بيانات وصاحب قرار
الإيقاف. لا يعاد فتح الموقع إذا كان آخر Full غير قابل للفحص أو إذا تجاوز
RTO الحد الأقصى المقبول دون قرار موثق.
