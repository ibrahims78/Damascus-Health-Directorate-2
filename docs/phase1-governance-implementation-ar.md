# المرحلة 1 — الحاكمية والصلاحيات (تنفيذ + توثيق)

**المشروع:** مديرية صحة دمشق — الإصدار **4.1.0** (المرحلة 1 من خطة العمل)
**التاريخ:** 2026-09-14
**الحالة:** ✅ منفَّذة ومُختبرة

---

## 1) الهدف

إحكام حاكمية التعريفات: **الكتالوج والبيانات المرجعية يملكها المدير**، وأمين المستودع ينفّذ
العمليات اليومية فقط. مع إصلاحات حماية مرتبطة (أرشفة بدل الحذف، حماية المراجع، قفل الهوية).

## 2) ما تغيّر

### أ) الخادم — مصفوفة الصلاحيات (الفرض على الخادم)
| العملية | قبل | بعد |
|---|---|---|
| إنشاء/تعديل/استيراد مادة | مدير + أمين مستودع | **مدير فقط** |
| أرشفة مادة | مدير | مدير |
| إنشاء/تعديل/استيراد/أرشفة تجهيز | مدير + أمين مستودع | **مدير فقط** |
| إنشاء مستلم (جهة) | مدير + أمين مستودع | **مدير فقط** |
| تصنيفات / أسباب الخروج / المستخدمون | مدير | مدير |
| القراءة (مواد/تجهيزات/تقارير) | الجميع | الجميع |
| العمليات (إدخال/إخراج/عهد/تلف/مرتجع/تسوية) | مدير + أمين مستودع | مدير + أمين مستودع |

### ب) الخادم — قواعد حماية جديدة
- **أرشفة التجهيزات** بدل الحذف الفعلي: `DELETE /api/equipment/:id` → `is_active = false` (وتُستثنى من كل القوائم).
- **رمز التجهيز (`code`) فريد**: تكرار ⇒ `409 EQUIPMENT_CODE_DUPLICATE` (إنشاء وتعديل).
- **حماية التصنيفات**: `DELETE /api/categories/:id` لم تصنيفًا مستخدمًا ⇒ `409 CATEGORY_IN_USE`.
- **قفل الهوية**: لا يمكن تغيير `code`/`unit` لمادة لها حركات ⇒ `409 ITEM_IDENTITY_LOCKED`.

### ج) المخطط وقاعدة البيانات
- جدول `equipment`: عمودان جديدان: `code` (فريد) و`is_active` (افتراضي `true`) + فهرس على الحالة.
- محدَّث في: `lib/db/src/schema/equipment.ts` · `lib/db/desktop-schema.sql` · سجل المزامنة `TABLE_REGISTRY` (مع `softDelete` للتجهيزات).

### د) الواجهة
- مسارات النماذج التعريفية **للمدير فقط**: `/items/new` · `/items/:id/edit` · `/equipment/new` · `/equipment/:id/edit` (عبر `ProtectedRoute adminOnly`).
- إخفاء زرّي **الإضافة** و**الاستيراد** عن أمين المستودع (علم `canDefine`).

## 4) التوافق والهجرة

- **إضافي بالكامل** (Additive): أعمدة جديدة بقيم افتراضية، لا حذف ولا تغيير نوع. قواعد المخطط تُطبَّق تلقائيًا عند الإقلاع (`ADD COLUMN IF NOT EXISTS`-style على مستوى المُهيّئ).
- **لا تأثير** على المزامنة: الأعمدة الجديدة مُدرَجة في سجل المزامنة.
- **التوافق مع النسخ السابقة**: بيانات قائمة تعمل كما هي؛ التجهيزات القديمة تأخذ `is_active = true` و`code = NULL`.

## 5) الرجوع (Rollback)

- إعادة ملفات المسارات/الواجهة إلى حالتها السابقة، وإعادة بناء الحزم.
- الأعمدة الجديدة غير ضارّة إن بقيت (يمكن تركها).
- ملاحظة: لا تُعاد التجهيزات المؤرشفة تلقائيًا؛ تُستعاد بـ`is_active = true` عند الحاجة.

- نقل تهيئة الرصيد الافتتاحي إلى مسار اعتماد (المرحلة 3).
