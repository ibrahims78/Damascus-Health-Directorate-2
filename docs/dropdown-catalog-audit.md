# تقرير تدقيق القوائم المنسدلة

## النطاق

تمت مراجعة جميع عناصر `Select` المستخدمة لإدخال بيانات أو اختيار كيان داخل
تطبيق مستودعات مديرية صحة دمشق. تم التفريق بين القوائم التي تحفظ قيمة في قاعدة
البيانات والقوائم الثابتة المستخدمة لتحديد حالة أو نوع معروف من النظام.

## القوائم المرتبطة بمصدر بيانات

| الخانة | مكان الاستخدام | مصدر الخيارات | القيمة المحفوظة | آلية التحقق والتعديل |
|---|---|---|---|---|
| التصنيف | إضافة/تعديل مادة | `GET /api/categories`، جدول `categories` | `categoryId` الرقمي | يمكن للمدير الإضافة والتعديل من **الإعدادات ← التصنيفات**. لا يتم إرسال اسم التصنيف مع المادة، بل معرّفه. |
| الوحدة | إضافة/تعديل مادة | `GET /api/settings` ثم `unitsList`، جدول `system_settings` | نص الوحدة | يمكن للمدير الإضافة وإعادة التسمية والحذف من **الإعدادات ← وحدات القياس**. يمنع النظام التكرار والقيمة الفارغة وحذف آخر وحدة، ويوجد خيار **أخرى** للإدخال اليدوي عند الحاجة. |
| المادة | إضافة/تعديل المادة، الإدخال والإخراج والتسوية والتلف والمرتجع المركزي | `GET /api/items`، جدول `items` | `itemId` الرقمي | الواجهة تعرض النشطة فقط، والخادم يسمح بجلب حتى 5000 خيار دون قص القوائم الكبيرة بصمت. |
| التجهيز | الإدخال وتسليم العهدة والتلف والمرتجع المركزي | `GET /api/equipment`، جدول `equipment` | `equipmentId` الرقمي | الواجهة تستخدم المعرّف الرقمي بدل الاسم، والخادم يسمح بجلب حتى 5000 خيار دون قص القوائم الكبيرة. |
| الجهة المستلمة | إخراج مادة وتسليم عهدة | `GET /api/recipients`، جدول `recipients` | `recipientId` الرقمي | القائمة العادية تعيد النشطة فقط. المدير يرى الكل ويديرها من **الإعدادات ← الجهات المستلمة**؛ التعديل والتعطيل لا يحذفان السجلات التاريخية. |
| سبب الإخراج | إخراج مادة | `GET /api/exit-reasons`، جدول `exit_reasons` | `exitReasonId` الرقمي | القائمة العادية تعيد النشطة فقط. المدير يضيف ويعدل الأسباب المخصصة ويعطلها من **الإعدادات ← أسباب الإخراج**؛ الأسباب الافتراضية محمية. |
| العهدة المفتوحة | إعادة عهدة | `GET /api/transactions/custodies` بعد تصفية `outstandingQuantity > 0` | `custodyId` الرقمي | لا تظهر العهد المغلقة أو المستنفدة، وتُعاد الكمية للتحقق قبل الإرسال. |

## القوائم الثابتة المقصودة

هذه القوائم ليست قاموسًا إداريًا، لذلك بقيت ثابتة حتى لا تؤثر التغييرات على
قواعد المخزون والتقارير:

- الحالة الفنية للتجهيز: جيد، يحتاج فحص، تحت الصيانة، معطل، مستهلك/متلف.
- حالة الصنف عند إعادة العهدة: جيد، تالف، يحتاج صيانة، مفقود.
- مكان التسليم: مبنى إداري، مرفق صحي.
- نوع التصنيف: مستهلكات، تجهيزات.
- دور المستخدم وحالته: مدير، مسؤول مستودع، مشاهد، نشط/معطل.
- نوع العملية في صفحات السجل والتقارير: مرشحات قراءة وليست بيانات مستندية.

## التعديلات المنفذة

1. تمت إضافة تصفية خادمية للجهات وأسباب الإخراج: لا تظهر العناصر المعطلة في
   نماذج الإدخال، بينما يمكن للمدير طلبها صراحة عبر
   `includeInactive=true`.
2. تمت إضافة تبويبي إدارة للجهات وأسباب الإخراج داخل الإعدادات.
3. يمكن تعديل الاسم والملاحظات للجهة، وإضافة جهة، وتعطيلها أو إعادة تفعيلها.
4. يمكن إضافة وتعديل وتعطيل أسباب الإخراج المخصصة. الأسباب الافتراضية محمية
   لمنع كسر دلالات السجل والتقارير.
5. أضيف تسجيل تدقيق لإنشاء وتعديل وتغيير حالة الجهات والأسباب.
6. بعد أي تغيير يتم تحديث قائمة الإدارة وقوائم نماذج الإدخال عبر إبطال Query
   Cache بالمفاتيح الفعلية لمسارات API، فلا يحتاج المستخدم إلى إعادة تحميل الصفحة.
7. تم تحديث OpenAPI وإعادة توليد عميل React وZod حتى تبقى أنواع الواجهة
   ومسارات API متطابقة.
8. تم إصلاح تعليمات استيراد المواد لتقرأ `/api/categories` كمصفوفة مباشرة، وهو
   الشكل الفعلي لعقد API.
9. تم توحيد استعلام إعدادات الوحدات بين صفحة الإعدادات ونموذج المادة، مع عرض
   الوحدة القديمة عند تعديل مادة إذا أزيلت من القاموس الإداري.
10. يتحقق الخادم من قائمة الوحدات قبل حفظها: عناصر نصية غير فارغة، بطول محدود،
    وفريدة بعد إزالة المسافات.
11. يعيد `GET /api/settings` قائمة الوحدات الافتراضية نفسها التي تعرضها شاشة
    الإدارة عند عدم وجود تخصيص محفوظ، حتى تظهر قائمة الوحدات في نموذج المادة
    من المصدر نفسه منذ أول تشغيل.
12. تم توحيد حد القوائم الكبيرة: نماذج اختيار المادة والتجهيز تطلب حتى 5000
    خيار، وواجهتا `/api/items` و`/api/equipment` تسمحان بالحد نفسه بدل قص
    القائمة بصمت عند حد صغير.
13. تم توحيد قوائم الكتالوج الكبيرة في مكوّن بحث قابل للتمرير، مع إصلاح
    ارتفاع `Select` العام حتى تظهر جميع خيارات القوائم الأخرى مع شريط تمرير
    واضح على الشاشات الصغيرة والكبيرة.

## جرد جميع عناصر Select

### قوائم إدخال بيانات تحفظ في النظام

| الخانة | الشاشة | القيمة المرسلة | المصدر والتحقق |
|---|---|---|---|
| التصنيف | إضافة/تعديل مادة، مرشح المواد | `categoryId` | `GET /api/categories`، معرّف رقمي، وإدارة الاسم من الإعدادات ← التصنيفات. |
| الوحدة | إضافة/تعديل مادة | `unit` نص الوحدة | `GET /api/settings` ← `unitsList`؛ يدعم الإضافة والتعديل والحذف الآمن، مع إدخال «أخرى». |
| المادة | إدخال/إخراج/تسوية/تلف/مرتجع | `itemId` | `GET /api/items`، المعرّف فقط، مع عرض الرصيد والوحدة للتحقق البصري. |
| التجهيز | إدخال/تسليم عهدة/تلف/مرتجع | `equipmentId` | `GET /api/equipment`، المعرّف فقط، مع عرض الرقم التسلسلي/الكمية/الحالة. |
| الجهة المستلمة | إخراج مادة وتسليم عهدة | `recipientId` | `GET /api/recipients`، النشطة فقط؛ الإدارة من الإعدادات مع تعديل وتعطيل وإعادة تفعيل. |
| سبب الإخراج | إخراج مادة | `exitReasonId` | `GET /api/exit-reasons`، النشطة فقط؛ الأسباب الافتراضية محمية والتخصيصات قابلة للتعديل. |
| العهدة المفتوحة | إعادة عهدة | `custodyId` | `GET /api/transactions/custodies`، بعد تصفية `outstandingQuantity > 0`. |

### قوائم ثابتة أو مرشحات قراءة

هذه القوائم لا تُدار من الإعدادات لأن قيمها جزء من عقد الحركة أو التقارير:

- نوع العملية: إدخال، إخراج، تسوية، تسليم عهدة، إعادة عهدة، تلف، مرتجع مركزي.
- نوع الصنف: مادة/مستهلك أو تجهيز/معدة.
- جهة التسليم: مبنى إداري أو مرفق صحي.
- الحالة الفنية للتجهيز: جيد، يحتاج فحص، تحت الصيانة، معطل، مستهلك/متلف.
- حالة الإعادة: جيد، تالف، يحتاج صيانة، مفقود.
- دور المستخدم وحالة الحساب: مدير، أمين مستودع، مراقب؛ نشط أو معطل.
- مرشحات سجل التدقيق وتقارير الحركات والعهد: لا تحفظ بيانات مستندية.

### مكان التعديل والصلاحيات

التعديل متاح للمدير من **الإعدادات**:

- **التصنيفات:** إضافة وتعديل الاسم والنوع، مع منع الحذف إذا كان التصنيف
  مرتبطاً بمواد.
- **وحدات القياس:** إضافة وتعديل وحذف، مع منع القائمة الفارغة والتكرار؛
  تعديل الخيار لا يغيّر قيمة المواد السابقة.
- **الجهات المستلمة:** إضافة وتعديل الاسم والملاحظات وتعطيل/تفعيل؛ التعطيل
  يخفي الخيار من النماذج ويحافظ على السجل التاريخي.
- **أسباب الإخراج:** إضافة وتعديل وتعطيل/تفعيل للأسباب المخصصة فقط؛ الأسباب
  الافتراضية محمية.

بعد كل تعديل تُبطل Query Cache الخاصة بالإدارة وبالنماذج، فتظهر القيمة الجديدة
دون إعادة تحميل الصفحة. الخادم يفرض الصلاحيات والتحقق مرة ثانية، لذلك لا يمكن
للمستخدم العادي تعديل مصدر قائمة عبر تغيير الواجهة.

## نتيجة الاختبار

- `pnpm --filter @workspace/api-spec codegen`: ناجح.
- `pnpm run typecheck`: ناجح لجميع حزم المكتبات والـ API والواجهة والسكريبتات.
- بناء الواجهة وبناء API: ناجحان، مع تحذير حجمي معتاد من Vite لبعض الحزم
  الكبيرة وتحذيرات sourcemap في مكونات UI دون فشل البناء.
- بناء وتشغيل خدمتي API والواجهة: ناجح، API على `8080` والواجهة على `22333`.
- تهيئة مخطط قاعدة التطوير عبر أمر المشروع الرسمي: ناجحة.
- اختبار القبول `phase8:acceptance`: ناجح، 7 فحوصات تشمل الصحة وCORS والصلاحيات
  والتقارير وتسجيل دخول المشاهد.
- اختبار API إداري مباشر: تسجيل المدير، قراءة التصنيفات والوحدات والمواد
  والتجهيزات والجهات والأسباب، والتحقق من أن القيم الكيانية أرقام وأن القوائم
  العادية لا تعيد غير النشط.
- اختبار إدارة الوحدات: إضافة مؤقتة، رفض قيمة غير صالحة، ثم الاستعادة: ناجح.
- اختبار دورة الجهة وسبب الإخراج: إضافة وتعديل وتعطيل وتصفية وإعادة تفعيل، ثم
  تنظيف بيانات الاختبار: ناجح.
- تحقق عقد قائمة المادة والتجهيز: طلب `limit=500` يعيد القيمة المعلنة نفسها
  ولا يخفي الخيارات بسبب سقف 200 القديم؛ وقائمة الوحدات الافتراضية تظهر من
  `GET /api/settings` قبل أي تخصيص: ناجح.
- اختبار الواجهة البصري: صفحة الدخول ظهرت سليمة، ولا توجد أخطاء TypeScript.

> يتطلب اختبار شاشة الإعدادات نفسها وجود جلسة مدير. نقاط API التي تغذيها
> اختُبرت بجلسة مدير، وتظل صلاحيات الإدارة محمية على الخادم.
