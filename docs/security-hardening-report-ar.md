## 2. تفصيل الإصلاحات

### 🔴 عالية الخطورة

**1. تجزئة كلمات المرور في الوضع دون اتصال (SHA-256 بجولة واحدة)**
- **الإصلاح:** `offline-api.ts` يستخدم الآن **PBKDF2-SHA-256 بـ 310,000 تكرار** عبر WebCrypto، بصيغة قابلة للترقية `pbkdf2$<iterations>$<hex>`.
- **التوافق:** كلمات المرور القديمة (SHA-256 legacy) **تتحقق بنجاح** وتُرقّى تلقائياً إلى PBKDF2 عند أول دخول ناجح.
- **الاختبار:** `docs/tests/offline-password.test.mjs` (8 اختبارات: الصيغة، الصحة، الرفض، الملح الخاطئ، التوافق مع القديم، حتمية الإخراج...). **8/8 ✅**

**2. بيانات الاعتماد الافتراضية المدمجة (admin / Admin@1234)**
- **الإصلاح:** الـ seed يولّد **كلمة مرور عشوائية (16 حرفاً)** تطبع مرة واحدة، ويعين `mustChangePassword = true`؛ أو يستخدم `SEED_ADMIN_PASSWORD` لبيئات التطوير/الاختبار صراحة.
- **الفرض في الواجهة:** عمود جديد `users.must_change_password` + استجابة الدخول تحمل العلم + صفحة `/change-password` جديدة تُفرض عبر حماية المسارات (App.tsx يُعيد التوجيه تلقائياً).
- **نقطة النهاية:** `POST /api/settings/change-password` حُدّث (bcrypt 12 + تصفير العلم). ملاحظة: المواصفة كانت تذكر المسار دون تنفيذ فعلي في مسار auth — أُعيد استخدام مسار settings الموجود.
- **الاختبار:** ضمن حزمة الأمان — seed حديث بدون متغير بيئة: كلمة المرور الافتراضية القديمة **ترفض (401)**، العشوائية تعمل، العلم يُفرض، التغيير ينجح، القديمة تُرفض بعدها. **✅**

**3. لا اختبارات آلية ولا CI/CD**
- **الإصلاح:**
  - `.github/workflows/ci.yml`: وظيفتان — (typecheck + build + lint معلوماتي) و (E2E على نسختين حيّتين عبر `scripts/ci-e2e.sh`).
  - `scripts/ci-e2e.sh`: يبني نسختين مؤقتتين من الصفر (مجلدات بيانات مؤقتة، seed بإعادة محاولة)، ثم يشغّل حزم المزامنة والأمان وكلمات المرور.
  - اختبارات جديدة: `api-security-tests.mjs` (13)، `offline-password.test.mjs` (8). الموجودة سابقاً: مزامنة (44) + تسوية (18).
- **ملاحظة:** الرفع إلى GitHub يحتاج دفع الفرع من جهتك (لا أملك بيانات دفع) — سير العمل جاهز وسيعمل تلقائياً عند الدفع.
- **الاختبار:** السكربت نفسه نُفّذ محلياً بالكامل: **ALL SUITES PASSED** (44 + 13 + 8).

### 🟠 متوسطة

**4. SheetJS 0.18.5 قديمة**
- **الإصلاح:** الترقية إلى **xlsx 0.20.3 من CDN الرسمي** (`cdn.sheetjs.com`) في `artifacts/web/package.json`.
- **الاختبار:** إعادة تثبيت pnpm + بناء الويب نجحا (الاستيراد الديناميكي لم يتغير).

**5. حد JSON بـ 64MB عام**
- **الإصلاح:** الحد العام أصبح **2MB**، مع استثناء 64MB فقط للمسارات التي تحتاجه فعلاً: `/api/backups`، `/api/backup`، `/api/sync/import`، `/api/sync/exchange`، `/api/items/bulk-import`، `/api/equipment/bulk-import`.
- **الاختبار:** جسم 3MB على `/api/auth/login` → **413** ✅

**6. مُحدد المعدل في الذاكرة**
- **الإصلاح:** جدول جديد `auth_rate_limits` في قاعدة البيانات (يبقى بعد إعادة التشغيل، مشترك بين النسخ على نفس القاعدة) + خدمة `lib/rate-limit.ts` (فحص/تسجيل/تصفير) موصولة بـ login وsetup.
- **الاختبار:** 9 فشل ثم نجاح → يصفّر العداد؛ 10 فشل → **429 مع Retry-After**. والقيد **استمر عبر إعادة تشغيل الخادم فعلياً** أثناء الاختبار (دليل عملي على الديمومة). ✅

**7. لا رؤوس أمان HTTP**
- **الإصلاح:** إضافة **helmet v8** مع CSP مضبوطة (default-src 'self'، frame-ancestors 'none'، worker blob: لمعالج المزامنة، ws: للتطوير) وتعطيل upgrade-insecure-requests (وضع سطح المكتب loopback HTTP).
- **الاختبار:** فحص الترويسات في الاستجابات. ✅

**8. لا توكن CSRF صريح**
- **الإصلاح:** نمط **Synchronizer Token**: توكن لكل جلسة يُصدر عند الدخول/التهيئة ويُعاد من `/api/auth/me`؛ الوسيط `lib/csrf.ts` يفرضه على كل POST/PUT/PATCH/DELETE **فقط** عندما يوجد Origin + جلسة (طلبات السكربتات والنظراء بـ Basic معفاة بطبيعتها — لا جلسة).
- **العميل:** `lib/csrf-client.ts` يحقن الترويسة تلقائياً في كل نداء /api متغيّر الحالة، ويُثبّت في main.tsx قبل طبقة الأوفلاين.
- **الاختبار:** Origin غريب → 403؛ توكن خاطئ → 403؛ توكن صحيح → 201؛ بدون Origin (سكربت) → نجاح. ✅

**9. تضخم ملفات الواجهة (settings.tsx = 2878 سطراً)**
- **الإصلاح:** التقسيم إلى **10 ملفات** تحت `pages/settings/`: index (الصدفة)، profile، password، activity، org، units، technical، backup، catalog (تصنيفات/جهات/أسباب)، import (مواد/تجهيزات) — مع نقل الأنواع والمساعدات المشتركة لكل وحدة.
- **الاختبار:** typecheck الويب 0 أخطاء + البناء الكامل نجح.

**10. release-artifacts/ يحوي 178MB ثنائيات (منها مجلد مفكوك ~150MB)**
- **الإصلاح:** حذف مجلد Electron المفكوك الخاص بالإصدار القديم من التتبع، إبقاء الأرشيفات + SHA256SUMS (الحجم المتبقي: **29MB**)، وتنظيف `.gitattributes` من قواعد LFS للملفات المحذوفة.
- **التوصية المتبقية:** رفع الأرشيفات إلى صفحة GitHub Releases عند الدفع (يحتاج صلاحيات الدفع).

**11. المزامنة بدون توقيع رقمي (non-repudiation)**
- **الإصلاح:** **Ed25519** كامل:
  - توليد زوج مفاتيح لكل عقدة عند أول استخدام (`node_identity.signing_public_key/private_key`، keyId = بصمة SHA-256 للنصف الأول).
  - توقيع كل طلب/استجابة تبادل (`x-dme-node/signed-at/signature`) والتحقق منها لدى النظير إذا كانت مفتاحية المرسل موثوقة — **الرفض 403 عند التلاعب**.
  - تبادل المفاتيح العمومية تلقائياً واستمرارها في `sync_trusted_nodes.signing_public_key`.
  - توقيع حزم `.dme-sync` في ترويسة الغلاف (بدون إعادة تشفير — التوقيع فوق checksum)، والتحقق عند الاستيراد (رفض عند فشل التحقق).
- **الاختبار:** أول تبادل → مفتاح النظير يُستلم؛ ثاني تبادل → **peerSignature: verified**؛ حزمة مصدّرة → **signatureVerification: verified** عند الاستيراد. ✅

### 🟡 منخفضة / بنيوية

**12. جلسة 7 أيام + bcrypt 10**
- **الإصلاح:** الجلسة **24 ساعة مع rolling** (تجديد انزلاقي) وsameSite strict؛ bcrypt **12 دورة** في setup وseed وتغيير كلمة المرور.
- **الاختبار:** فحص سمات الكوكي في الاستجابة ✅

**13. APK موقّع بمفتاح debug**
- **الإصلاح:** `android/app/build.gradle` يقرأ `RELEASE_KEYSTORE_PATH/PASSWORD/ALIAS` من البيئة: عند توفرها يوقّع بمفتاح الإصدار، وإلا يوقّع debug مع **تحذير صريح** أثناء البناء. التوثيق ضمن هذا التقرير (توليد keystore يبقى خطوة تشغيلية عندكم لأنه سرّي).
- **حد ثابت:** إنتاج APK موقّع فعلياً يتطلب keystore خاصاً لا يمكن توليده هنا.

**14. ترحيلات Drizzle للإنتاج**
- **الإصلاح:** `lib/db/drizzle.config.ts` + سكربتا `db:generate` / `db:migrate` + توليد **الترحيل الابتدائي** `migrations/0000_*.sql` من المخطط الكامل (18 جدولاً). مسار سطح المكتب يبقى بالـ schema الذاتي الإصلاح عند الإقلاع.
- **ملاحظة:** لأخذ ترحيلات لاحقة: عدّل المخطط ثم `pnpm --filter @workspace/db db:generate`.

**15. لا ESLint**
- **الإصلاح:** `eslint.config.js` (flat config) مع typescript-eslint + react-hooks، وسكربت `pnpm lint`، وخطوة lint في CI.
- **النتيجة الأولية:** **0 أخطاء، 813 تحذيراً تراثياً** (موثقة؛ القاعدة الحادة معطلة مؤقتاً وCI يجعل الخطوة معلوماتية حتى تُصفّى التحذيرات تدريجياً).

**16. أداء التقارير والبحث (اختياري)**
- **الحالة:** مقصود تأجيله كتحسين اختياري (caching/materialized views، pg_trgm للبحث العربي) — ليست عيوباً وظيفية بل توسعات مستقبلية مع نمو البيانات.
