# ضمانات عقد المزامنة

## خصائص العمليات

| العملية | idempotent | مرتبة | commutative | قابلة للإعادة | قابلة للتراجع |
|---|---|---|---|---|---|
| تسجيل تغيير محلي | لا، يولد هوية جديدة | حسب origin sequence | لا | لا دون operationId | عبر correction |
| تصدير من متجه | نعم لنفس الجلسة والمتجه | نعم حسب العقدة والتسلسل | لا | نعم | لا يعدل المصدر |
| تطبيق حزمة | نعم لنفس operationId والحمولة | نعم داخل كل origin | لا | نعم | عبر قرار conflict/restore |
| حذف كيان | نعم مع tombstone | نعم حسب المصدر | لا | نعم | correction/restore |
| حل conflict reject | نعم للحالة المحلولة | لا | لا | نعم | قرار تصحيحي جديد |
| حل conflict correct | لا؛ يولد change جديدًا | نعم بعد التسجيل | لا | نعم بعد operationId | correction لاحق |

## الضمانات المثبتة

1. لا يطبق `operationId` مرتين إذا تطابقت الحمولة.
2. اختلاف الحمولة لنفس العملية يتحول إلى `OPERATION_PAYLOAD_MISMATCH`.
3. التسلسل الناقص يوقف تطبيق المجموعة برسالة `SYNC_SEQUENCE_GAP`.
4. كل تغيير جديد يسجل في inbox وسجل التغيير قبل اكتمال التقرير.
5. فشل materialization يعزل التغيير عبر SAVEPOINT ويكتب تعارضًا.
6. الحزمة المعدلة تفشل checksum أو MAC قبل فك المحتوى.
7. المرجع المفقود لا يسقط بصمت؛ إما يعالج ضمن قائمة المراجع المتسامحة أو
   يسجل `MISSING_REFERENCE`.
8. الحذف يترك tombstone ولا يسمح لحزمة قديمة بإحياء الكيان.
9. كلمة مرور الحزمة لا تدخل manifest أو السجل.
10. المستخدمون لا ينقلون password hashes؛ ينشأ حساب وارد بكلمة غير قابلة
    للدخول ويعاد ضبطه محليًا.

## حدود الضمان

- التقارب يعتمد على وصول الحزم وعدم حذف السجلات أو tombstones قبل أوانها.
- لا يوجد ترتيب عالمي بين عقدتين؛ الترتيب مضمون لكل origin فقط.
- تعارضات الرصيد والعهد تحتاج قرارًا بشريًا ولا تحلها قاعدة عامة آلية.
- الاختبار الحالي صناعي ولا يثبت سعة شبكة أو جهاز إنتاج بعينه.
- المزامنة اليدوية لا تعني توفرًا لحظيًا؛ لحظة النقل مسؤولية التشغيل.
