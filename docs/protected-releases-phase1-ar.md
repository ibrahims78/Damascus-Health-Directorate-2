# تقرير تنفيذ المرحلة الأولى — النسخ المحمية لـ Windows وAndroid

تاريخ التنفيذ: 22 أغسطس 2026  
النطاق: المرحلة الأولى فقط من `protected-releases-work-plan-ar.txt`

## القرار

تم تنفيذ المرحلة الأولى على مستوى البنية وأوامر البناء والفحوصات الآلية. لم يتم تنفيذ أي بند من
المراحل 2–9، بما في ذلك إنشاء مفاتيح جديدة، تشفير البيانات، تغليف Electron، توقيع APK/EXE،
أو اعتماد إصدار إنتاجي.

## ما تم تنفيذه

### 1. تثبيت خط الأساس

- تم تثبيت المشروع على الفرع `main`.
- تم توثيق نقطة البداية في مستودع Git نفسه عبر commit الحالي.
- تم الحفاظ على أوامر التشغيل الحالية للواجهة والـ API دون تغيير.
- بقيت قاعدة بيانات Replit وملفات التطبيق خارج نطاق تغيير هذه المرحلة.

### 2. نقاط الدخول ومسارات التشغيل

| المكوّن | نقطة الدخول | التشغيل |
|---|---|---|
| الواجهة | `artifacts/web/src/main.tsx` | Vite على المنفذ 22333 |
| API | `artifacts/api-server/src/index.ts` | Express على المنفذ 8080 |
| Android | `capacitor.config.ts` + `android/` | Capacitor مع `artifacts/web/dist/public` |
| Offline | `artifacts/web/src/lib/offline-api.ts` | يتفعّل عبر `VITE_OFFLINE_MODE=1` |
| Protected gate | `artifacts/web/src/components/protected-build-gate.tsx` | يتفعّل عبر `VITE_PROTECTED_BUILD=1` |
| Desktop database path | `lib/db/src/index.ts` | PGlite عند `DAMASCUS_DESKTOP=1` |

### 3. مراجعة Offline وPGlite والمزامنة

- الواجهة تملك مسار Offline مستقلًا يعتمد على IndexedDB.
- إعداد Capacitor يوجه الحزمة إلى مخرجات الواجهة.
- طبقة قاعدة البيانات تميز بين PostgreSQL المستضاف ووضع PGlite المكتبي.
- منطق الهوية والمزامنة المشترك موجود في `lib/db` و`lib/sync-contract`.
- لم يتم تغيير هذه الأجزاء في المرحلة الأولى؛ تمت مراجعتها وتوثيق نقاط استخدامها فقط.

### 4. فصل standard وprotected

أضيفت أوامر منفصلة:

```text
pnpm run build:standard
pnpm run build:protected
```

ومقابلاتها داخل حزم الواجهة والـ API.

مخرجات النسخة العادية:

```text
artifacts/web/dist/public/
artifacts/api-server/dist/
```

مخرجات النسخة المحمية:

```text
artifacts/web/dist/protected/public/
artifacts/api-server/dist/protected/
```

هذا الفصل يمنع أن تمسح عملية بناء محمية مخرجات النسخة العادية أو تستخدمها بالخطأ.
الفصل البنائي لا يعني أن جميع حماية الترخيص أصبحت مكتملة؛ دمج الترخيص وإعدادات المنصات
جزء من المراحل اللاحقة.

### 5. منع خلط الأسرار

تمت إضافة قواعد تجاهل لمواد الإصدار الحساسة، منها:

- ملفات `.env`.
- ملفات `jks` و`keystore`.
- ملفات `p12` و`pfx`.
- ملفات `pem` و`key`.
- مفاتيح خاصة بأسماء واضحة.
- مجلدات `release-secrets/` و`release-staging/`.

كما أضيف فحص آلي في:

```text
scripts/phase1-build-boundary-smoke.mjs
```

يفحص:

1. الملفات المتتبعة في Git بحثًا عن مواد توقيع أو أسرار.
2. قواعد `.gitignore` المطلوبة.
3. وجود مخرجات standard وprotected في مسارات منفصلة.
4. محتوى المخرجات الصغيرة بحثًا عن مؤشرات مفاتيح خاصة أو أسرار شائعة.

## الاختبارات المنفذة

الأوامر المستخدمة:

```text
pnpm install --frozen-lockfile
pnpm run build:standard
pnpm run build:protected
pnpm --filter @workspace/scripts run phase1:build-boundary
pnpm run typecheck
pnpm run build
```

كما تم التحقق من:

- تشغيل الواجهة والـ API في Replit.
- استجابة الواجهة HTTP 200.
- عدم وجود ملفات حساسة متتبعة في Git.
- عدم تداخل مخرجات البناء بين standard وprotected.
- بقاء الفرع المحلي متطابقًا مع baseline قبل تغييرات هذه المرحلة.

## ما بقي خارج المرحلة الأولى

لا تعتبر البنود التالية منفذة بهذا التقرير:

- إنشاء وإدارة زوج مفاتيح الإصدار.
- اعتماد سياسة الترخيص والإبطال والانتهاء.
- اختبارات License Core الشاملة.
- معرّف جهاز Windows أو Android Native.
- تشويش ملفات الإنتاج.
- تشفير البيانات المحلية والنسخ الاحتياطية.
- Electron wrapper جديد أو تحسينه.
- توقيع APK أو Windows Authenticode.
- اختبار أجهزة Windows/Android الفعلية.
- إصدار إنتاجي أو قرار Go/No-Go.
