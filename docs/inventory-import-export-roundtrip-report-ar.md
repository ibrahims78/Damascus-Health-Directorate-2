# تقرير التصدير وإعادة الاستيراد

**تاريخ التنفيذ:** 2026-09-10  
**إصدار النموذج:** `4.0`  
**بيئة الاختبار:** API Desktop/PGlite مع قاعدة مؤقتة، SheetJS، LibreOffice

## سيناريو الاختبار

1. إنشاء مادة اختبار برمز ثابت ودفعتين بصلاحيتين مختلفتين.
2. تصدير المواد والدفعات ذات الرصيد المتبقي من API.
3. تحويل الاستجابة إلى XLSX برؤوس النموذج.
4. فتح الملف وإعادة قراءته.
5. رفعه في وضع `upsert`.
6. مقارنة الرصيد والدفعات والرموز والتواريخ.
7. إعادة رفع الملف الأصلي في وضع `insert` للتحقق من رفض التكرار.

## النتيجة

| التحقق | النتيجة |
|---|---|
| تصدير مادة ودفعتين | ناجح |
| إعادة فتح XLSX | ناجح |
| بقاء الرمز والأصفار البادئة | ناجح |
| بقاء أرقام الدفعات والتواريخ | ناجح |
| معاينة ملف التصدير | ناجح؛ الدفعات الموجودة تظهر بتحذير |
| `upsert` التعريفي | ناجح؛ تحديث مادة واحد دون إنشاء دفعات |
| ثبات الرصيد | ناجح؛ بقي الرصيد `12` |
| منع تكرار الدفعات | ناجح؛ `DUPLICATE_EXISTING_BATCH` |
| إعادة الملف في `insert` | ناجح؛ رفض `DUPLICATE_CODE` وHTTP `422` |
| FEFO بعد الدورة | ناجح؛ اختار الدفعة الأقرب أولًا |

## قرار التنفيذ

أضيفت حماية على مستوى الفحص المسبق تعتمد المفتاح المركب للدفعة. عند وجود دفعة
مطابقة في قاعدة الهدف، لا تنشئ المعاملة حركة جديدة. هذا يجعل إعادة رفع تصدير
المخزون عملية تعريفية idempotent ولا يغير الرصيد بصمت.

## حدود الاختبار

الاختبار يستخدم بيانات اصطناعية. لم تُستخدم بيانات مستودع فعلية، ولم يُعتمد فتح
الملف في نسخة Excel تجارية أو Google Sheets ضمن بيئة الاختبار الحالية.
