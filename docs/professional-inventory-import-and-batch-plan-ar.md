# خطة احترافية لتوحيد المواد والدفعات واستيراد Excel

**المشروع:** مستودعات مديرية صحة دمشق
**نوع الوثيقة:** خطة تنفيذ واختبار وتوثيق شاملة  
**الحالة:** مكتملة برمجيًا واختباريًا — بانتظار اعتماد تشغيلي يدوي لبرامج Excel التجارية وقياس أداء الملفات الكبيرة
**النطاق:** شاشة المواد، الدفعات، حركات الإدخال، استيراد Excel، التصدير، العمل دون اتصال، الاختبارات والتوثيق  
**اللغة المعتمدة في واجهة المستخدم:** العربية  
**المرجع الزمني:** 2026-09-09

---

## 1. الهدف التنفيذي

تهدف هذه الخطة إلى تحويل دورة إدارة المواد والاستيراد من Excel إلى دورة احترافية ودقيقة وقابلة للتدقيق، بحيث تكون:

1. **بيانات المادة الأساسية منفصلة** عن بيانات الدفعات والتوريد.
2. **تاريخ الصلاحية ورقم الدفعة مرتبطين بالدفعة الفعلية** التي تستخدمها خوارزمية FEFO، وليس بسجل المادة العام فقط.
3. **نموذج Excel الفارغ قابلًا للتحميل والتعبئة دون التباس**.
4. **الملف المعبأ قابلًا للاستيراد بعد فحص مسبق واضح**.
5. **التصدير وإعادة الاستيراد متوافقين** مع نفس قاموس الأعمدة.
6. **الإضافة والتحديث لا يغيران الرصيد بصمت** ولا يتجاوزان سجل الحركات.
7. **الوضع المتصل والوضع دون اتصال يطبقان القواعد نفسها**.
8. **كل مرحلة قابلة للاختبار والتوثيق والرجوع الآمن**.
9. **النتيجة النهائية قابلة للمراجعة الإدارية والمحاسبية والمخزنية**.

هذه الوثيقة ليست تنفيذًا للتعديلات، بل هي خطة العمل التفصيلية التي يجب اتباعها قبل تغيير الكود أو قاعدة البيانات.

## 2. الوضع الحالي والمشكلات التي تعالجها الخطة

### 2.1 نموذج المادة الحالي

توجد في نموذج إضافة المادة حقول تخص المادة نفسها، إلى جانب حقول تخص دفعة توريد أو رصيد افتتاحي، ومن أهمها:

- اسم المادة.
- الرمز الداخلي.
- التصنيف.
- الوحدة.
- الحد الأدنى.
- الموقع.
- الملاحظات.
- الرصيد الافتتاحي أو الحالي.
- تاريخ الصلاحية.
- رقم الدفعة.
- المورد.

المشكلة ليست في وجود الحقول منفردة، بل في خلط مستويات البيانات في نموذج واحد. المادة قد تستمر لسنوات، بينما الصلاحية ورقم الدفعة يتغيران مع كل توريد.

### 2.2 مشكلة الدفعة الافتتاحية

عند إنشاء مادة برصيد افتتاحي، يتم إنشاء سجل دفعة افتتاحية، لكن بيانات تاريخ الصلاحية ورقم الدفعة المدخلة من النموذج أو Excel لا تنتقل دائمًا إلى سجل الدفعة الفعلي. ينتج عن ذلك احتمال اختلاف البيانات الظاهرة في المادة عن البيانات المستخدمة في FEFO والتقارير.

### 2.3 اختلاف مسارات Excel

يوجد أكثر من مسار للاستيراد:

- مسار في إعدادات الاستيراد.
- مسار في شاشة المواد.
- مسار دون اتصال.

وتختلف بينها:

- أسماء الأعمدة المقبولة.
- المرادفات.
- طريقة عرض المعاينة.
- قواعد التحقق.
- سلوك التحديث.
- التعامل مع التصنيف.
- التعامل مع الرصيد والدفعات.

### 2.4 اختلاف أسماء الأعمدة

توجد اختلافات بين:

- `تاريخ الانتهاء`.
- `تاريخ الصلاحية`.
- `الكمية الحالية`.
- `الرصيد الحالي`.
- `الاسم *`.
- `الاسم`.

يجب أن يدعم النظام قاموسًا مركزيًا واحدًا، لا خرائط منفصلة داخل كل شاشة.

### 2.5 مشكلة التحديث الجماعي

وضع `upsert` الحالي قد يحدّث الرصيد الحالي مباشرة عند وجود الرمز، دون إنشاء حركة جرد أو توريد أو تسوية موثقة. هذا غير مناسب لإدارة مخزون تعتمد على التتبع.

### 2.6 مشكلات الجودة قبل الاستيراد

المعاينة الحالية محدودة، ولا تكشف بشكل كافٍ:

- تكرار الرمز داخل الملف.
- تشابه الاسم والوحدة مع مادة موجودة.
- التواريخ غير الصحيحة.
- التصنيفات غير المطابقة.
- فقدان الأصفار في الرموز والباركود.
- الفرق بين تحديث البيانات التعريفية وتغيير الرصيد.
- الحقول المهمة مثل رقم الدفعة والصلاحية والمورد.

## 3. المبادئ التي يجب ألا تخالفها عملية التنفيذ

### 3.1 مبدأ الفصل بين المستويات

يجب الفصل بين:

#### أ. تعريف المادة

- الرمز الداخلي.
- الباركود.
- الاسم.
- التصنيف.
- الوحدة.
- الحد الأدنى.
- الموقع الأساسي.
- الملاحظات العامة.

#### ب. تعريف الدفعة

- المادة المرتبطة.
- الكمية.
- رقم الدفعة أو التشغيلة.
- تاريخ الصلاحية.
- المورد.
- رقم مذكرة التسليم أو المرجع.
- تاريخ التوريد أو الإدخال.
- ملاحظات الدفعة.

#### ج. الحركة المخزنية

- نوع الحركة.
- الكمية.
- التاريخ.
- المستخدم.
- المرجع.
- سبب الحركة.
- الدفعات المتأثرة.
- الرصيد قبل وبعد الحركة.

### 3.2 مبدأ عدم تغيير الرصيد بصمت

لا يجوز أن يؤدي تحديث بيانات المادة إلى تغيير الرصيد الحالي دون:

- حركة مسجلة.
- سبب واضح.
- مستخدم منفذ.
- وقت التنفيذ.
- مرجع العملية.

### 3.3 مبدأ المصدر الواحد للقواعد

يجب أن تستخدم الواجهة والخادم والوضع دون اتصال:

- نفس أسماء الحقول المنطقية.
- نفس قواعد التحقق.
- نفس قواعد التطبيع.
- نفس تفسير الكمية والتاريخ.
- نفس قواعد مطابقة التصنيف.

### 3.4 مبدأ قابلية التراجع

كل مرحلة تتضمن تغييرًا في قاعدة البيانات أو سلوك الاستيراد يجب أن تتضمن:

- نسخة احتياطية أو نقطة استعادة.
- ترحيلًا قابلًا للتتبع.
- خطة توافق مع البيانات القديمة.
- طريقة لإيقاف الميزة الجديدة دون فقد البيانات.

### 3.5 مبدأ التوافق التدريجي

يجب عدم كسر الملفات القديمة فورًا. يفضل:

1. دعم أسماء الأعمدة القديمة مؤقتًا.
2. تحويلها إلى النموذج الداخلي الموحد.
3. إصدار تحذير للمستخدم.
4. توثيق موعد إيقاف الأسماء القديمة.

## 4. التصميم المستهدف

## 4.1 نموذج المادة المستهدف

يحتوي تعريف المادة على:

| الحقل | الإلزام | القاعدة |
|---|---:|---|
| الرمز الداخلي | نعم | فريد، نصي، يحافظ على الأصفار البادئة |
| الباركود | لا | نصي، ويمكن فرض فرادته إذا كانت سياسة المؤسسة تتطلب ذلك |
| اسم المادة | نعم | غير فارغ، مع تطبيع المسافات |
| التصنيف | حسب سياسة المؤسسة | يطابق تصنيفًا معروفًا أو يظهر تحذير صريح |
| الوحدة | نعم | قيمة من قائمة الوحدات المعتمدة |
| الحد الأدنى | لا | عدد صحيح أو عشري غير سالب حسب نوع الوحدة |
| الموقع الأساسي | لا | موقع معروف أو قيمة نصية موثقة |
| الملاحظات العامة | لا | لا تتضمن بيانات دفعة متغيرة |

لا يتضمن نموذج تعريف المادة:

- تاريخ صلاحية دفعة محددة.
- رقم دفعة محددة.
- مورد توريد محدد.
- كمية توريد متغيرة.

## 4.2 نموذج الدفعة المستهدف

يحتوي سجل الدفعة على:

| الحقل | الإلزام | القاعدة |
|---|---:|---|
| المادة أو الرمز الداخلي | نعم | يجب أن يشير إلى مادة معروفة |
| الكمية | نعم عند إنشاء دفعة | أكبر من صفر |
| رقم الدفعة | حسب سياسة المادة | نصي، وليس رقمًا حسابيًا |
| تاريخ الصلاحية | حسب طبيعة المادة | تاريخ ISO بصيغة `YYYY-MM-DD` |
| المورد | حسب سياسة المؤسسة | يربط بمورد معروف أو يسجل كنص مضبوط |
| رقم المرجع | نعم للرصيد الافتتاحي | رقم مذكرة أو مستند واضح |
| تاريخ المرجع | نعم للرصيد الافتتاحي | تاريخ صالح |
| الملاحظات | لا | معلومات خاصة بالدفعة |

## 4.3 نمط Excel الموصى به

### النموذج المهني الأساسي: ملف بورقتين

#### الورقة الأولى: `المواد`

الرؤوس القياسية:

```text
الرمز الداخلي
الباركود
اسم المادة
التصنيف
الوحدة
الحد الأدنى
الموقع الأساسي
ملاحظات المادة
```

#### الورقة الثانية: `الأرصدة والدفعات الافتتاحية`

الرؤوس القياسية:

```text
الرمز الداخلي
الكمية الافتتاحية
رقم الدفعة
تاريخ الصلاحية
المورد
رقم المرجع الافتتاحي
تاريخ المرجع
ملاحظات الدفعة
```

يسمح هذا النموذج بوجود عدة صفوف دفعات مرتبطة بالمادة نفسها، وهو أمر لا يمكن تمثيله بشكل صحيح إذا تم إجبار كل مادة على صف واحد فقط.

### نموذج مبسط اختياري

يمكن توفير نموذج بورقة واحدة للمنشآت الصغيرة، بشرط تسمية حقول الدفعة بوضوح:

```text
الرمز الداخلي
اسم المادة
التصنيف
الوحدة
الحد الأدنى
الموقع الأساسي
الرصيد الافتتاحي
رقم الدفعة الافتتاحية
تاريخ صلاحية الدفعة الافتتاحية
المورد الافتتاحي
رقم المرجع الافتتاحي
تاريخ المرجع الافتتاحي
ملاحظات
```

هذا النموذج لا يغني عن نموذج الورقتين عندما يكون للمادة أكثر من دفعة.

## 5. قواعد Excel المهنية

يجب أن يحقق نموذج Excel الفارغ المتطلبات التالية:

1. يحتوي على أسماء أوراق ثابتة ومعلنة.
2. يحتوي على ورقة تعليمات منفصلة.
3. يوضح الحقول المطلوبة دون استخدام نجمة داخل اسم العمود نفسه.
4. يعرض الحقول المطلوبة في ورقة التعليمات وفي وصف الأعمدة.
5. ينسق الرمز والباركود كنص.
6. ينسق التواريخ بصيغة `YYYY-MM-DD`.
7. يمنع القيم السالبة في الكميات والحد الأدنى.
8. يضيف قوائم منسدلة للتصنيف والوحدة إذا كان ذلك ممكنًا دون ربط هش ببيئة المستخدم.
9. يثبت الصف الأول ويجعله واضحًا بصريًا.
10. يضع عرضًا مناسبًا للأعمدة العربية.
11. لا يحتوي على بيانات تجريبية داخل ورقة البيانات.
12. يضع المثال في ورقة التعليمات أو ورقة أمثلة منفصلة.
13. يوضح أن الرصيد الافتتاحي ليس تحديثًا صامتًا لرصيد موجود.
14. يوضح كيفية ربط دفعة بمادة باستخدام الرمز الداخلي.
15. يوضح أن الرمز والباركود لا يجب أن يعاملا كأرقام.
16. يوضح صيغة التاريخ المقبولة ومثالًا صحيحًا ومثالًا خاطئًا.
17. يوضح السلوك عند ترك التصنيف أو المورد فارغًا.
18. يحتوي على رقم إصدار للنموذج داخل ورقة التعليمات.
19. يحتوي على تاريخ إصدار النموذج.
20. يحتوي على سياسة توافق واضحة مع الملفات القديمة.

# 6. مراحل التنفيذ والاختبار والتوثيق

## المرحلة 0: تثبيت خط الأساس وحماية البيانات

**حالة التنفيذ:** مكتملة في 2026-09-10. أُنشئت نسخة احتياطية محلية قبل الترحيل،
وحُفظت fixtures اصطناعية، ونُفذ فحص API معزول قابل لإعادة التشغيل؛ التفاصيل في
`docs/inventory-import-batch-baseline-and-db-review-2026-09-09-ar.md`.

### الهدف

توثيق السلوك الحالي وحماية البيانات قبل أي تعديل.

### التنفيذ

1. إنشاء نسخة احتياطية من بيانات التطوير.
2. تسجيل إصدار Git الحالي ونقطة البداية.
3. توثيق المخطط الحالي لجداول المواد والدفعات والحركات.
4. حصر جميع نقاط إنشاء المادة.
5. حصر جميع نقاط إنشاء الدفعة.
6. حصر جميع مسارات استيراد Excel.
7. حصر مسار التصدير.
8. حصر مسار العمل دون اتصال.
9. حفظ عينة ملفات:
   - نموذج فارغ حالي.
   - ملف صادر من النظام.
   - ملف يحتوي على مادة جديدة.
   - ملف يحتوي على دفعة.
   - ملف يحتوي على أخطاء متعمدة.
10. تحديد السلوك الذي يجب الحفاظ عليه لأسباب التوافق.

### الاختبار

1. تشغيل فحص الأنواع.
2. تشغيل بناء الواجهة والخادم.
3. فحص `/api/healthz`.
4. إنشاء مادة يدوية.
5. تسجيل إدخال لدفعة.
6. تصدير المواد.
7. استيراد ملف بسيط.
8. فحص ظهور الدفعة في شاشة التفاصيل.
9. فحص تأثير FEFO على الصرف.
10. تسجيل النتائج الحالية حتى يمكن مقارنة النتائج بعد التنفيذ.

### التوثيق

إنشاء تقرير خط أساس يتضمن:

- الإصدار.
- الأوامر المستخدمة.
- النتائج.
- عينات الإدخال.
- النتائج المتوقعة والفعلية.
- المشكلات المعروفة.

### معيار الخروج

لا تبدأ المراحل التالية قبل توفر:

- نسخة احتياطية.
- تقرير خط أساس.
- ملفات اختبار محفوظة.
- طريقة مؤكدة لإعادة تشغيل البيئة.

## المرحلة 1: تثبيت تعريفات المجال وقواعد العمل

**حالة التنفيذ:** مكتملة توثيقيًا في 2026-09-09 — لم تُنفذ تغييرات قاعدة البيانات أو الواجهة ضمن هذه المرحلة.
**المخرج الرئيسي:** [قواعد المجال المعتمدة للمواد والدفعات والحركات](materials-batches-domain-rules-ar.md)

### الهدف

اعتماد تعريف رسمي للمادة والدفعة والحركة قبل تعديل قاعدة البيانات أو الواجهة.

### التنفيذ

1. تحديد الحقول الأساسية للمادة.
2. تحديد الحقول الخاصة بالدفعة.
3. تحديد الحقول الخاصة بالحركة.
4. اعتماد الرمز الداخلي كمفتاح المطابقة الأساسي.
5. تحديد سياسة المواد التي لا تملك رمزًا.
6. تحديد هل الباركود فريد أم لا.
7. تحديد الوحدات المقبولة.
8. تحديد سياسة التصنيفات غير المعروفة.
9. تحديد المواد التي تتطلب تاريخ صلاحية.
10. تحديد المواد التي تتطلب رقم دفعة.
11. تحديد قواعد الكمية العشرية أو الصحيحة.
12. تحديد ما إذا كان الموقع جزءًا من المادة أو من الدفعة أو من المخزون الموجود في موقع.
13. تحديد معنى الرصيد الافتتاحي بدقة.
14. تحديد الفرق بين:
    - الرصيد الافتتاحي.
    - التوريد.
    - التسوية.
    - التحديث التعريفي.
15. تحديد سياسة التحديث عند وجود رمز موجود.

### الاختبار

إجراء مراجعة سيناريوهات على الورق أو في جدول قرار:

1. مادة جديدة بلا رصيد.
2. مادة جديدة برصيد ودفعة واحدة.
3. مادة جديدة برصيد بعدة دفعات.
4. مادة موجودة مع تحديث الاسم فقط.
5. مادة موجودة مع محاولة تغيير الرصيد.
6. مادة بلا رمز.
7. رمزان متشابهان بعد إزالة المسافات.
8. دفعة بلا صلاحية لمادة لا تحتاج صلاحية.
9. دفعة بلا صلاحية لمادة تتطلب صلاحية.
10. تصنيف غير موجود.

### التوثيق

إنشاء أو تحديث وثيقة قواعد العمل لتحتوي على:

- قاموس المصطلحات.
- قواعد الإلزام.
- قواعد التحقق.
- قواعد المطابقة.
- قواعد التحديث.
- قواعد الدفعات.
- أمثلة صحيحة وخاطئة.

### معيار الخروج

اعتماد قرار واضح لكل سيناريو، وعدم ترك سلوك يعتمد على التخمين أثناء التنفيذ.

## المرحلة 7: تنفيذ API للاستيراد بشكل ذري وقابل للتدقيق

### الهدف

تنفيذ الاستيراد بطريقة تمنع الحفظ الجزئي وتفصل تحديث المادة عن إنشاء الدفعة.

### التنفيذ

1. إضافة نقطة فحص مسبق إن لزم.
2. اعتماد نموذج طلب واضح للإضافة والتحديث والدفعات.
3. التحقق من البيانات في الخادم حتى لو تم تجاوز الواجهة.
4. إعادة التحقق من الرمز والوحدة والتصنيف والتاريخ.
5. منع الاعتماد على فحص الواجهة وحده.
6. استخدام معاملة قاعدة بيانات مناسبة.
7. تحديد سياسة المعاملة:
   - كل الملف ينجح أو يفشل.
   - أو تقسيم واضح إلى دفعات مع تقرير كامل.
8. عدم إنشاء مادة وترك دفعتها ناقصة.
9. عند إنشاء مادة برصيد افتتاحي:
   - إنشاء المادة.
   - إنشاء الدفعة.
   - نقل رقم الدفعة.
   - نقل الصلاحية.
   - نقل المرجع.
   - تسجيل الحركة.
10. عند وجود مادة مسبقًا:
    - تحديث الحقول التعريفية فقط في وضع التحديث.
    - عدم تغيير الرصيد دون مسار حركة صريح.
11. عند إنشاء دفعة:
    - منع الكمية الصفرية أو السالبة.
    - تطبيق قواعد الصلاحية.
    - حفظ المورد والمرجع.
12. منع إنشاء دفعة يتيمة.
13. إعادة نتيجة مفصلة لكل صف.
14. تسجيل المستخدم والوقت ومصدر العملية.
15. تسجيل إصدار نموذج Excel المستخدم.
16. توفير مفتاح تعقب للعملية.
17. منع إعادة تنفيذ نفس الملف بطريقة تسبب ازدواجية إن كان المرجع أو مفتاح العملية موجودًا.
18. تعريف سلوك واضح للرموز المكررة في الملف.

### الاختبار

1. إضافة مادة جديدة دون دفعة.
2. إضافة مادة جديدة مع دفعة واحدة.
3. إضافة مادة جديدة بعدة دفعات.
4. تحديث بيانات مادة موجودة.
5. محاولة تحديث الرصيد من وضع التعريفات.
6. استيراد دفعة لمادة موجودة.
7. استيراد دفعة لمادة غير موجودة.
8. فشل صف في منتصف الملف.
9. انقطاع الطلب أثناء التنفيذ.
10. إعادة إرسال نفس الطلب.
11. تكرار المرجع.
12. تكرار الرمز في الملف.
13. تصنيف غير موجود.
14. تاريخ صلاحية منتهي.
15. مادة تتطلب صلاحية دون تاريخ.
16. بيانات مورد غير صالحة.
17. التحقق من عدم بقاء بيانات جزئية بعد الفشل.
18. التحقق من تسجيل الحركة والدفعة والمادة معًا.

### التوثيق

توثيق:

- عقد API.
- نماذج الطلب والاستجابة.
- حالات HTTP.
- أكواد الأخطاء.
- حدود المعاملة.

## المرحلة 8: تحديث شاشة إضافة المادة وشاشة إدخال التوريد

### الهدف

### التنفيذ

1. إزالة أو إعادة تسمية الحقول المتغيرة من نموذج تعريف المادة.
2. إبقاء حقول المادة الأساسية فقط.
3. إضافة خيار واضح للرصيد الافتتاحي عند الحاجة.
4. ربط خيار الرصيد الافتتاحي بتدفق إنشاء دفعة.
5. التأكد من أن رقم الدفعة والصلاحية يذهبان إلى الدفعة.
6. تحديث شاشة تسجيل الإدخال لتكون المصدر الرئيسي للدفعات.
7. توحيد أسماء:
   - تاريخ الصلاحية.
   - رقم الدفعة.
   - المورد.
   - المرجع.
8. إظهار الحقول الإلزامية حسب نوع المادة.
9. منع إدخال رصيد افتتاحي دون تفسير.
10. عرض ملخص العملية قبل الحفظ.
11. عرض رقم الدفعة أو المرجع بعد النجاح.
12. تحديث شاشة التفاصيل لتعرض:
    - المادة.
    - رصيدها.
    - دفعاتها.
    - صلاحية كل دفعة.
    - رقم كل دفعة.
    - مصدرها.

### الاختبار

1. إنشاء مادة بدون رصيد.
2. إنشاء مادة برصيد افتتاحي.
3. إنشاء مادة برصيد افتتاحي ورقم دفعة وصلاحية.
4. إنشاء مادة بكمية صفر.
5. تسجيل إدخال جديد لمادة موجودة.
6. تسجيل إدخال بعدة دفعات متتابعة.
7. التحقق من FEFO.
8. التحقق من عدم ظهور صلاحية دفعة على مادة أخرى.
9. التحقق من رسائل الأخطاء.
10. التحقق من تعديل مادة دون تعديل دفعاتها.

### التوثيق

تحديث دليل المستخدم ليشرح:

- الفرق بين إضافة مادة وتسجيل إدخال.
- معنى الرصيد الافتتاحي.
- متى يستخدم رقم الدفعة.
- متى تكون الصلاحية مطلوبة.
- كيفية مراجعة الدفعات بعد الحفظ.

### معيار الخروج

لا يوجد حقل مكرر دون سبب مفهوم، ويمكن للمستخدم معرفة المكان الصحيح لإدخال كل قيمة.

## المرحلة 9: توحيد التصدير وإعادة الاستيراد

### الهدف

جعل الملف الذي يصدره النظام قابلًا لإعادة الاستيراد دون فقدان أو تغيير في المعنى.

### التنفيذ

1. جعل التصدير يستخدم قاموس الرؤوس القياسي.
2. تصدير المواد في ورقة المواد.
3. تصدير الدفعات في ورقة الدفعات عند الحاجة.
4. عدم تسمية `تاريخ الصلاحية` مرة و`تاريخ الانتهاء` مرة أخرى في الملفات الجديدة.
5. تضمين نسخة النموذج.
6. الحفاظ على الرموز كنص.
7. الحفاظ على التواريخ بصيغة ثابتة.
8. تحديد ما إذا كان الملف للتقارير فقط أو لإعادة الاستيراد.
9. إذا كان الملف للتقارير فقط، وضع تنبيه يمنع اعتباره ملف استيراد.
10. دعم إعادة استيراد ملف صادر حديثًا في بيئة اختبار.

### الاختبار

1. تصدير بيانات تحتوي على:
   - مادة بلا دفعات.
   - مادة بدفعة واحدة.
   - مادة بعدة دفعات.
   - رمز بأصفار بادئة.
   - صلاحية.
2. إعادة استيراد الملف في وضع الفحص فقط.
3. مقارنة البيانات قبل وبعد.
4. التحقق من عدم إنشاء مواد مكررة.
5. التحقق من عدم فقدان الدفعات.
6. التحقق من عدم تغيير الرصيد دون عملية صريحة.
7. اختبار التصدير ثم الاستيراد في بيئة مختلفة.

### التوثيق

توثيق:

- الفرق بين ملف التقرير وملف الاستيراد.
- الأعمدة التي تصدر.
- طريقة إعادة الاستيراد.
- القيود المعروفة.

### معيار الخروج

تنجح دورة `تصدير ← فحص ← إعادة استيراد` دون فقد البيانات أو تغيير معناها.

## المرحلة 10: توحيد العمل دون اتصال

### الهدف

منع اختلاف نتائج الاستيراد بين الخادم الرئيسي والعمل دون اتصال.

### التنفيذ

1. تطبيق نفس قاموس الرؤوس.
2. تطبيق نفس قواعد التحقق.
3. تطبيق نفس قواعد الرمز والتاريخ والكمية.
4. تطبيق نفس قواعد التكرار.
5. تطبيق نفس فصل المادة عن الدفعة.
6. تحديد ما يمكن تنفيذه دون اتصال.
7. تسجيل العمليات المحلية في قائمة مزامنة.
8. منع فقدان رقم العملية عند المزامنة.
9. تحديد تعارضات التحديث.
10. منع الكتابة فوق بيانات أحدث دون سياسة تعارض.
11. عرض نتيجة المزامنة للمستخدم.
12. الاحتفاظ بتقرير فشل الصفوف التي لم تتم مزامنتها.

### الاختبار

1. استيراد ملف صحيح دون اتصال.
2. استيراد ملف خاطئ دون اتصال.
3. مقارنة النتيجة مع الخادم.
4. إنشاء مادة ودفعة دون اتصال ثم مزامنتها.
5. انقطاع الاتصال أثناء المزامنة.
6. إعادة المزامنة.
7. تكرار العملية.
8. تعارض تحديث مادة.
9. تعارض دفعة.
10. التأكد من عدم مضاعفة الرصيد.

### التوثيق

توثيق:

- حدود العمل دون اتصال.
- أنواع العمليات المؤجلة.
- حالات التعارض.
- سياسة إعادة المحاولة.
- رسائل المزامنة.

### معيار الخروج

البيانات التي تمر عبر الوضع دون اتصال لا تحصل على معنى مختلف عند وصولها إلى الخادم.

## المرحلة 11: تحسين الأمان والأداء وقابلية الاستخدام

### الهدف

جعل عملية الاستيراد آمنة ومفهومة وقابلة للعمل مع ملفات كبيرة ضمن الحدود المعتمدة.

### التنفيذ

1. فرض حد حجم الملف.
2. فرض حد عدد الصفوف.
3. رفض الملفات التالفة.
4. منع تنفيذ صيغ أو شيفرات داخل الملف.
5. عدم عرض بيانات غير مصرح بها في تقرير الأخطاء.
6. تطبيق صلاحيات الاستيراد والتحديث.
7. تسجيل المستخدم المنفذ.
8. منع طلبات الاستيراد المتزامنة غير المقصودة.
9. عرض تقدم المعالجة للملفات الكبيرة.
10. تجنب تحميل بيانات ضخمة كاملة إلى الواجهة إذا لم يلزم.
11. توفير تنزيل لتقرير النتائج.
12. جعل عناصر المعاينة قابلة للاستخدام عبر لوحة المفاتيح.
13. دعم قارئات الشاشة للحالات والأخطاء.
14. عرض رسائل عربية واضحة.
15. عدم الاعتماد على لون الخطأ وحده.

### الاختبار

1. ملف يتجاوز الحجم.
2. ملف يتجاوز عدد الصفوف.
3. ملف مصمم لإدخال صيغة.
4. مستخدم بلا صلاحية.
5. مستخدم يملك صلاحية الإضافة دون التحديث.
6. استيراد متزامن.
7. ملف كبير ضمن الحد.
8. تشغيل بطيء أو انقطاع مؤقت.
9. استخدام كامل بلوحة المفاتيح.
10. اختبار نصوص الخطأ مع قارئ شاشة إن أمكن.

### التوثيق

توثيق:

- الحدود التشغيلية.
- الصلاحيات.
- السجل التدقيقي.
- سياسة الملفات الكبيرة.
- رسائل المستخدم.
- متطلبات المتصفح.

### معيار الخروج

لا يسمح النظام بعملية غير مصرح بها أو ملف يتجاوز الحدود، ولا تكون رسائل الفشل غامضة.

## المرحلة 12: التوثيق التشغيلي والتدريب

### الهدف

تحويل السلوك الجديد إلى إجراء واضح للمستخدمين والمشرفين.

### التنفيذ

1. تحديث دليل المستخدم.
2. تحديث دليل مدير النظام.
3. إنشاء دليل خاص باستيراد Excel.
4. إنشاء دليل خاص بالرصيد الافتتاحي.
5. إنشاء دليل خاص بالدفعات والصلاحيات.
6. إضافة أمثلة لملفات صحيحة.
7. إضافة أمثلة لملفات خاطئة.
8. شرح الفرق بين الإضافة والتحديث والتوريد.
9. شرح عدم تغيير الرصيد من خلال تحديث التعريف.
10. شرح معنى كل حالة في المعاينة.
11. شرح كيفية تنزيل تقرير الأخطاء.
12. توثيق إجراءات النسخ الاحتياطي قبل الاستيراد الكبير.
13. توثيق إجراءات معالجة الفشل.
14. توثيق إجراءات التراجع.

### الاختبار

1. إعطاء الدليل لمستخدم غير مطلع على التنفيذ.
2. طلب منه تنزيل النموذج.
3. تعبئة مادة ودفعتين.
4. رفع الملف.
5. معالجة خطأ متعمد.
6. إعادة رفع الملف بعد التصحيح.
7. مراجعة الدفعات بعد النجاح.
8. التأكد من أن المستخدم لا يحتاج شرحًا شفهيًا غير موثق.

### التوثيق

يجب أن تكون الأدلة النهائية داخل المشروع، وأن تشير إلى:

- إصدار النموذج.
- إصدار التطبيق.
- تاريخ آخر تحديث.
- المسؤول عن المراجعة.
- طريقة الإبلاغ عن مشكلة.

### معيار الخروج

يستطيع مستخدم مدرب حديثًا تنفيذ العملية كاملة اعتمادًا على الدليل.

# 7. المرحلة الإضافية: الاختبار الشامل النهائي والتوثيق النهائي

هذه المرحلة إلزامية، ولا تعتبر الخطة مكتملة دونها. هدفها اختبار كل ما تم تنفيذه كمنتج واحد، وليس اختبار الأجزاء منفصلة فقط.

## 7.1 تجهيز بيئة الاختبار

1. إنشاء قاعدة اختبار منفصلة.
2. تهيئة حسابات بصلاحيات مختلفة.
3. إنشاء تصنيفات ووحدات وموردين ومواقع اختبار.
4. تجهيز مواد:
   - مادة بلا دفعة.
   - مادة بدفعة منتهية.
   - مادة بدفعة قريبة الانتهاء.
   - مادة بعدة دفعات.
   - مادة برمز يبدأ بأصفار.
   - مادة بباركود.
5. حفظ نسخة من قاعدة الاختبار قبل بداية الجولة.
6. تسجيل إصدار الكود والنموذج.

## 7.2 اختبار تنزيل النموذج الفارغ

يجب التحقق من:

1. نجاح التنزيل من كل نقطة واجهة مسموحة.
2. فتح الملف دون تحذير تلف.
3. وجود الأوراق الصحيحة.
4. تطابق الرؤوس مع القاموس القياسي.
5. وجود التعليمات.
6. وضوح الحقول المطلوبة.
7. سلامة تنسيق الرموز.
8. سلامة تنسيق التواريخ.
9. سلامة القوائم المنسدلة.
10. عدم وجود بيانات اختبارية في ورقة البيانات.
11. ظهور إصدار النموذج.
12. قابلية فتح الملف في أكثر من برنامج.

## 7.3 اختبار تعبئة نموذج صحيح

إنشاء ملف يحتوي على:

### مواد

- مادة جديدة بلا رصيد.
- مادة جديدة برمز رقمي الشكل لكنه نصي.
- مادة جديدة برمز بأصفار بادئة.
- مادة بتصنيف معروف.

### دفعات

- دفعة أولى.
- دفعة ثانية للمادة نفسها.
- صلاحيتان مختلفتان.
- موردان مختلفان.
- مرجعان مختلفان.

ثم التحقق من:

1. قراءة كل الصفوف.
2. ظهور كل الأعمدة في المعاينة.
3. اعتبار كل الصفوف صالحة.
4. عرض العدد الصحيح للمواد والدفعات.
5. نجاح الاستيراد.
6. إنشاء المواد دون تكرار.
7. إنشاء الدفعات بالبيانات الصحيحة.
8. حفظ الصلاحيات في الدفعات.
9. حفظ أرقام الدفعات دون تغيير.
10. إنشاء الحركات أو المراجع المطلوبة.
11. ظهور الرصيد الصحيح.
12. عمل FEFO بالشكل المتوقع.

## 7.4 اختبار ملف يحوي أخطاء

إنشاء ملف يحتوي على:

1. اسم فارغ.
2. وحدة فارغة.
3. رمز مكرر.
4. رمز مفقود في ورقة الدفعات.
5. تصنيف غير موجود.
6. وحدة غير موجودة.
7. كمية سالبة.
8. كمية نصية غير مفهومة.
9. تاريخ غير صالح.
10. تاريخ منتهي لمادة تتطلب صلاحية.
11. رقم دفعة فارغ في حالة إلزامه.
12. مرجع افتتاحي مفقود.
13. أعمدة قديمة.
14. أعمدة مجهولة.
15. صف فارغ.
16. رمز يفقد صفره البادئ.

يجب التحقق من:

- اكتشاف كل خطأ.
- ذكر رقم الصف.
- ذكر اسم العمود.
- توضيح سبب الخطأ.
- منع الحفظ عند الخطأ الحرج.
- عدم إنشاء بيانات جزئية.
- إمكانية تنزيل تقرير الأخطاء.

## 7.5 اختبار الإضافة والتحديث

### الإضافة فقط

1. إضافة مادة جديدة تنجح.
2. مادة موجودة تفشل برسالة واضحة.
3. رمز مكرر داخل الملف يفشل قبل الحفظ.
4. الدفعة الافتتاحية تنشأ مرة واحدة.

### تحديث البيانات التعريفية

1. تحديث الاسم ينجح.
2. تحديث الوحدة يخضع للقيود.
3. تحديث التصنيف ينجح أو يعطي تحذيرًا واضحًا.
4. تحديث الرصيد ممنوع في هذا المسار.
5. الدفعات القائمة لا تتغير.

### استيراد الدفعات

1. إضافة دفعة لمادة موجودة تنجح.
2. إضافة دفعة لمادة غير موجودة تفشل أو تتطلب إنشاء المادة وفق السياسة المعتمدة.
3. الصلاحية ورقم الدفعة يحفظان في جدول الدفعات.
4. الحركة تسجل بالمستخدم والتاريخ والمرجع.

## 7.6 اختبار التصدير وإعادة الاستيراد

1. إنشاء بيانات متنوعة.
2. تصديرها.
3. فتح الملف وفحص الرؤوس.
4. إعادة رفعه في وضع الفحص.
5. التأكد من عدم وجود فقد.
6. التأكد من عدم تغيير الرموز.
7. التأكد من بقاء التواريخ.
8. التأكد من بقاء الدفعات المتعددة.
9. التأكد من أن الملف لا يغير الرصيد تلقائيًا عند استخدام وضع التعريفات.

## 7.7 اختبار الوضع دون اتصال

1. تنزيل أو تجهيز النموذج.
2. فصل الاتصال.
3. تنفيذ استيراد صحيح.
4. تنفيذ استيراد خاطئ.
5. حفظ العملية محليًا.
6. إعادة الاتصال.
7. مزامنة العملية.
8. مقارنة النتيجة مع المسار المتصل.
9. اختبار تكرار المزامنة.
10. اختبار تعارض التعديل.
11. التحقق من عدم مضاعفة الدفعة أو الرصيد.

## 7.8 اختبار الصلاحيات والأمان

1. مستخدم قراءة فقط.
2. مستخدم إضافة.
3. مستخدم تحديث.
4. مدير.
5. رفع ملف كبير.
6. رفع ملف تالف.
7. محاولة تجاوز الواجهة بطلب مباشر.
8. محاولة تنفيذ تحديث غير مصرح.
9. التأكد من تسجيل المستخدم.
10. التأكد من عدم تسريب بيانات غير لازمة في رسالة الخطأ.

## 7.9 اختبار الأداء

1. ملف صغير.
2. ملف متوسط.
3. ملف عند الحد الأقصى.
4. قياس زمن الفحص.
5. قياس زمن المعاينة.
6. قياس زمن الحفظ.
7. مراقبة استهلاك الذاكرة.
8. التأكد من عدم تجمّد الواجهة.
9. اختبار إعادة المحاولة بعد فشل مؤقت.

## 7.10 اختبار الترحيل والتوافق

1. قاعدة قديمة تحتوي على بيانات.
2. تطبيق الترحيل.
3. قراءة المواد القديمة.
4. قراءة الدفعات القديمة.
5. عرض المواد في الواجهة.
6. تنفيذ تصدير.
7. تنفيذ استيراد جديد.
8. التأكد من عدم حذف حقول التوافق قبل انتهاء الحاجة إليها.

# 12. المرحلة التنفيذية المستقلة المدرجة بالخطة

## 12.1 المهمة المستقلة الأولى: منع فقدان بيانات الدفعات وجعل استيراد Excel قابلًا للتدقيق

**الحالة:** مكتملة برمجيًا واختباريًا في 2026-09-10؛ الاعتماد التشغيلي اليدوي موثق كإجراء لاحق
**نوعها:** حزمة تنفيذ مستقلة ضمن هذه الخطة  
**سبب إدراجها:** هذه المهمة تجمع التغييرات التي لا يصح تنفيذها منفردة؛ لأن تعديل نموذج Excel دون تعديل الدفعات أو API قد ينتج ملفًا يبدو صحيحًا لكنه يحفظ بيانات غير دقيقة.

### الهدف

تنفيذ الدورة الكاملة التي تربط:

```text
تعريف المادة
→ الدفعة الافتتاحية
→ حركة الإدخال
→ نموذج Excel
→ الفحص والمعاينة
→ API
→ التصدير وإعادة الاستيراد
→ الوضع دون اتصال
→ الاختبار والتوثيق
```

بحيث لا تضيع بيانات:

- رقم الدفعة.
- تاريخ الصلاحية.
- المورد.
- رقم المرجع.
- الرصيد الافتتاحي.

### نطاق التنفيذ

#### أ. توحيد نموذج البيانات

1. فصل حقول تعريف المادة عن حقول الدفعة.
2. اعتماد الرمز الداخلي كمفتاح المطابقة الأساسي.
3. تعريف نموذج موحد للمواد.
4. تعريف نموذج موحد للدفعات.
5. تعريف نموذج موحد لحركات الإدخال.
6. تحديد الحقول الإلزامية حسب نوع المادة.
7. تحديد سياسة المواد التي لا تملك رمزًا.

#### ب. إصلاح إنشاء الدفعات

1. نقل رقم الدفعة إلى سجل الدفعة الفعلي.
2. نقل تاريخ الصلاحية إلى سجل الدفعة الفعلي.
3. نقل المورد والمرجع وتاريخه.
4. إنشاء حركة افتتاحية قابلة للتدقيق.
5. منع إنشاء دفعة يتيمة.
6. التأكد من أن FEFO يقرأ القيم الجديدة.
7. منع الاعتماد على حقول قديمة في جدول المادة كمصدر وحيد للصلاحية أو الدفعة.

#### ج. إعادة بناء نموذج Excel

1. إنشاء ورقة `المواد`.
2. إنشاء ورقة `الأرصدة والدفعات الافتتاحية`.
3. إنشاء ورقة `التعليمات`.
4. توحيد رؤوس الأعمدة.
5. إضافة إصدار النموذج.
6. تنسيق الرموز والباركود كنص.
7. تنسيق التواريخ بصيغة `YYYY-MM-DD`.
8. إضافة قواعد التحقق والقوائم المرجعية عند الإمكان.
9. توضيح الفرق بين تحديث البيانات وإضافة دفعة.
10. دعم أكثر من دفعة للمادة نفسها.

#### د. توحيد القراءة والفحص

1. استخدام قارئ Excel مركزي.
2. دعم الرؤوس القياسية.
3. دعم المرادفات القديمة مع تحذير توافق.
4. كشف الرؤوس المكررة أو المجهولة.
5. كشف الصفوف الفارغة.
6. كشف الرموز المكررة.
7. كشف تشابه الأسماء والوحدات.
8. كشف التصنيفات والوحدات غير المعروفة.
9. كشف التواريخ غير الصالحة.
10. الحفاظ على الأصفار البادئة.
11. عرض نتيجة فحص لكل صف.
12. منع الحفظ قبل معالجة الأخطاء الحرجة.

#### هـ. إصلاح API وسلوك التحديث

1. التحقق من البيانات في الخادم.
2. استخدام معاملة مناسبة للاستيراد.
3. ربط إنشاء المادة بإنشاء دفعتها عند وجود رصيد افتتاحي.
4. عدم تغيير الرصيد مباشرة في تحديث البيانات التعريفية.
5. إنشاء حركة موثقة عند استيراد دفعة أو رصيد افتتاحي.
6. تسجيل المستخدم والوقت ومصدر العملية.
7. إعادة تقرير مفصل لكل صف.
8. منع التكرار عند إعادة إرسال العملية.
9. منع بقاء بيانات جزئية عند فشل الاستيراد.

#### و. تحديث الواجهات والوضع دون اتصال

1. إزالة التكرار بين نموذج المادة ونموذج إدخال التوريد.
2. إظهار خيار الرصيد الافتتاحي بطريقة صريحة.

6. تسجيل العمليات المؤجلة للمزامنة.
7. منع مضاعفة الدفعات أو الأرصدة عند إعادة المزامنة.

### شروط إعادة فتح المهمة

لا تعاد حالة المهمة إلى «قيد التنفيذ» قبل تحقق الشروط التالية:

- نسخة احتياطية قابلة للاستعادة من قاعدة التطوير.
- تقرير خط أساس مكتمل ببيانات اختبار معزولة.
- اعتماد سياسة ترحيل الحقول القديمة في `items`.
- اعتماد سياسة الصلاحية ورقم الدفعة على مستوى المادة أو الفئة.
- اعتماد مفتاح منع التكرار وإعادة الاستيراد.
- اعتماد الصلاحيات ومسار التحديث دون تغيير الرصيد.

**قرار البوابة التاريخي:** `مستقل-001` كانت **مؤجلة بقرار موثق** في
2026-09-09. أُغلقتا المرحلتان 0 و2 لاحقًا في 2026-09-10، لكن المهمة بقيت
مؤجلة لأن نطاقها يبدأ من المرحلة 3 ويشمل استيراد Excel المهني.

# 13. سياسة إدراج المهام المستقلة اللاحقة

عند ظهور مهمة مستقلة جديدة مرتبطة بهذه الخطة، يجب إدارتها بالطريقة التالية:

1. تحديد سبب الحاجة إلى المهمة وعلاقتها بدورة المواد أو Excel.
2. التأكد من أنها ليست مكررة لمرحلة موجودة.
3. إضافة سجل لها داخل هذا الملف قبل تنفيذها.
4. إعطاؤها عنوانًا واضحًا يصف قيمة المهمة أو الخطر الذي تعالجه.
5. تسجيل:
   - الحالة.
   - الهدف.
   - النطاق.
   - المتطلبات السابقة.
   - التنفيذ.
   - الاختبار.
   - التوثيق.
   - مخرجات القبول.
   - الملفات أو المجالات المرجعية.
6. عدم بدء تنفيذها تلقائيًا بمجرد إضافتها.
7. إرسال إشعار للمستخدم عند إضافتها.
8. تحديث حالتها عند بدء التنفيذ أو توقفه أو اكتماله.
9. إضافة تقرير الاختبار والتوثيق بعد اكتمالها.
10. عدم حذف المهمة القديمة عند إلغائها؛ بل تسجيل حالتها وسبب الإلغاء للحفاظ على أثر القرار.

## 13.1 المهمة المستقلة الثالثة: إغلاق خط الأساس واعتماد ترحيل قاعدة البيانات قبل بدء استيراد Excel

**المعرّف:** مستقل-003
**الحالة:** مقترحة ولم تبدأ
**النوع:** بوابة جاهزية واعتماد قبل التنفيذ
**العلاقة:** شرط سابق لإعادة فتح `مستقل-001`، ومكمل لمراجعة `مستقل-002`

### الهدف

إغلاق متطلبات المرحلة 0 واعتماد تصميم المرحلة 2 قبل تنفيذ التغييرات المترابطة في المواد والدفعات واستيراد Excel، مع منع أي تغيير غير قابل للتراجع في بيانات المخزون.

### النطاق

#### أ. إغلاق خط الأساس

1. إنشاء نسخة احتياطية قابلة للاستعادة من قاعدة التطوير.
2. تجهيز قاعدة اختبار أو بيانات اختبار منزوعة البيانات الحقيقية.
3. حفظ نموذج Excel فارغ وملفات اختبار صحيحة وخاطئة.
4. تسجيل سلوك الإنشاء والإدخال والتصدير والاستيراد وFEFO قبل التعديل.
5. توثيق طريقة استعادة النسخة الاحتياطية ونتائج الفحوص.

#### ب. اعتماد تصميم قاعدة البيانات والترحيل

1. مراجعة العلاقة بين `items` و`inventory_batches` و`transactions`.
2. اعتماد سياسة ترحيل `expiryDate` و`batchNumber` القديمة.
3. تحديد سياسة الدفعات التي تفتقد رقم دفعة أو صلاحية أصلية.
4. اعتماد سياسة `requiresExpiryTracking` و`requiresBatchTracking` أو البديل الرسمي لها.
5. اعتماد الحركة والمرجع المطلوبين للدفعة الافتتاحية والتوريد.
6. اعتماد مفتاح منع التكرار لإعادة الاستيراد والمزامنة.
7. تحديد الحقول القديمة التي ستبقى للقراءة فقط وموعد إيقاف الاعتماد عليها.

#### ج. قرار بوابة البدء

1. مراجعة نتائج خط الأساس ومراجعة قاعدة البيانات معاً.
2. تسجيل المخاطر والقرارات غير المحسومة.
3. تحديث حالة المرحلة 0 والمرحلة 2 في تقرير الخروج.
4. إعادة فتح `مستقل-001` فقط إذا اكتملت شروط البدء.

### المتطلبات السابقة

1. اعتماد قواعد المجال في المرحلة 1.
2. توفر قاعدة تطوير وقاعدة اختبار منفصلتين.
3. توفر صلاحية إنشاء نسخة احتياطية واستعادتها.
4. عدم استخدام بيانات مخزون فعلية في ملفات الاختبار.

### خطة الاختبار

1. استعادة النسخة الاحتياطية في بيئة اختبار منفصلة.
2. تشغيل الترحيل على قاعدة فارغة.
3. تشغيل الترحيل على قاعدة تحتوي على بيانات اختبار.
4. التحقق من عدم فقد المواد أو الدفعات أو الحركات.
5. التحقق من القيود غير السالبة والفهارس وعلاقات الدفعات.
6. التحقق من أن FEFO يقرأ سجل الدفعة الصحيح.
7. إعادة تشغيل الترحيل أو العملية للتحقق من عدم التكرار.
8. تسجيل أي اختلاف بين السلوك الحالي والقواعد المعتمدة.

### التوثيق المطلوب

1. تقرير خط أساس مكتمل.
2. تقرير نسخة احتياطية واستعادة.
3. تقرير مراجعة وتصميم الترحيل.
4. سجل قرارات التوافق مع الحقول القديمة.
5. سجل سياسة منع التكرار وإعادة الاستيراد.
6. تحديث حالة `مستقل-001` والمرحلتين 0 و2.

### مخرجات القبول

1. نسخة احتياطية تم اختبار استعادتها بنجاح.
2. ملفات اختبار معزولة ونتائج خط أساس قابلة لإعادة التشغيل.
3. تصميم ترحيل معتمد وقابل للتراجع.
4. إثبات عدم فقد بيانات في قاعدة الاختبار.
5. قرارات الحقول القديمة وسياسات الدفعات والتكرار موثقة.
6. قرار واضح: فتح `مستقل-001` أو إبقاؤها مؤجلة مع سبب.
