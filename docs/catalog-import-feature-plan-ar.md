# خطة تنفيذ ميزة «استيراد الكتالوج» (المواد والتجهيزات) — v1.0

**المشروع:** Damascus Health Directorate — 4.3.0
**الغرض:** استيراد ملف Excel فارغ يملؤه المدير لتعريف/إضافة المواد والتجهيزات إلى الكتالوج، مع إمكانية الإضافة لاحقاً.
**المبدأ الحاكم:** فصل صريح بين «الكتالوج (تعريفات)» و«الأرصدة والدفعات (حركات)». قالب الكتالوج **لا يتضمن أي أعمدة كمية**.

---

## المراحل

### المرحلة 0 — التمهيد
- المخرجات: هذا الملف، وتحديث قاموس Excel (`docs/inventory-import-excel-dictionary-ar.md`) بقسم «قالب الكتالوج».
- معيار القبول: وثيقة خطة + قاموس محدّث + قائمة رموز الأخطاء/التحذيرات.

### المرحلة 1 — العقد المشترك (lib/api-zod)
- ملف عقد جديد للكتالوج بجانب `inventory-import.ts`:
  - `CATALOG_TEMPLATE_VERSION = "1.0"`
  - `CATALOG_SHEET_NAMES` (المواد / التجهيزات / القيم المرجعية / التعليمات)
  - `CATALOG_ITEM_COLUMNS`, `CATALOG_EQUIPMENT_COLUMNS`
  - تطبيع الرؤوس/الأرقام/التواريخ + مرادفات عربية (إعادة استخدام دوال الموجود)
  - `validateCatalogItemRows` / `validateCatalogEquipmentRows`
  - مفاتيح التكرار: مواد `code` وإلا (name+unit)؛ تجهيزات `serial` وإلا (name+model)
  - رموز الأخطاء: `NAME_REQUIRED`, `UNIT_UNKNOWN`, `CATEGORY_UNKNOWN`, `DUP_KEY_IN_FILE`, `DUP_KEY_EXISTING`, `SERIAL_WITH_QTY`, `INVALID_ACTIVE_FLAG`, …
- اختبارات: `catalog-import.test.ts` (vitest).
- معيار القبول: اختبارات خضراء + تغطية الحالات الحرجة.

### المرحلة 2 — الخادم (api-server)
- `POST /api/catalog/import/preview` (تحليل + قرارات + إحصاءات، بلا كتابة)
- `POST /api/catalog/import` (تنفيذ ذرّي داخل معاملة)
- أوضاع: `add-only` / `add-and-update`.
- **مصدر الوحدات = كتالوج الوحدات** (لا `DEFAULT_INVENTORY_UNITS`).
- منع تعديل كمية تجهيز موجود؛ تطبيق «تسلسلي ⇒ كمية = 1».
- تدقيق: حدث لكل كيان (create/update) مع `source: catalog-import`.
- صلاحية: مدير فقط.
- توثيق المسارات في `lib/api-spec/openapi.yaml` + إعادة توليد العميل.
- معيار القبول: اختبارات تكامل + عدم أي كتابة في مسار preview.

### المرحلة 3 — الواجهة (web)
- تبويب «استيراد الكتالوج» في `artifacts/web/src/pages/settings/import.tsx`:
  - تنزيل النموذج (يُبنى من كتالوج الوحدات/التصنيفات/المستودعات).
  - رفع الملف + معاينة + ملخص أرقام + تنزيل تقرير الأخطاء.
  - اختيار الوضع، وتعطيل زر التنفيذ عند الخطأ الحرج.
- دعم RTL وأخطاء واضحة لكل صف.
- معيار القبول: بناء الواجهة ينجح + جولة يدوية على ملفات عينة.

### المرحلة 4 — الأوفلاين
- نفس القواعد في `offline-api.ts` مع **تمرير مفاتيح الموجود مسبقاً** لمنع التكرار.
- معيار القبول: إعادة رفع نفس الملف دون تضاعف.

### المرحلة 5 — الجودة والتوثيق والتسليم
- ملفات عينة (صحيح/خطأ/مختلط) في `fixtures/catalog-import/`.
- تشغيل كامل للاختبارات (`vitest`) + تدقيق lint/build للمسّات.
- تحديث `CHANGELOG.md` + دليل المستخدم `docs/user-guide-ar.md`.
- تسليم تقرير نتائج نهائي.

## قواعد إلزامية
- لا لمس `Releases/` ولا أصول الإصدار على GitHub.
- لا تعديل على ملفات الترخيص/التفعيل.
- لا `git push` (الالتزام محلي فقط) دون موافقة.
- لا حذف ملفات قائمة.
- بعد كل مرحلة: commit محلي برسالة واضحة.
- أي عائق ⇒ يُسجَّل في `catalog-import-progress.md` ويُتابع لا يُترك معلّقاً.

## معايير القبول النهائية
1. استيراد ملف كتالوج بورقتين (مواد + تجهيزات) ينجح، ويضيف لاحقاً بلا تكرار.
2. لا يمكن لأي مسار في الميزة تغيير أرصدة أو دفعات.
3. الوحدات/التصنيفات مصدرها الكتالوج الفعلي.
4. `preview` لا يكتب؛ `import` ذرّي.
5. اختبارات وحدة + تكامل خضراء، وبناء الواجهة ينجح.
6. توثيق: قاموس Excel + OpenAPI + CHANGELOG + دليل المستخدم.
