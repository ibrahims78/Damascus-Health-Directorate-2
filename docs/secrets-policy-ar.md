# سياسة الأسرار وسلسلة التوريد

## القواعد

- لا تُحفظ الأسرار أو ملفات `.env` أو مفاتيح التوقيع الخاصة في Git.
- `SESSION_SECRET` مطلوب قبل تشغيل API في وضع PostgreSQL.
- وضع Desktop لا يحتاج السر لبدء التطبيق، لكنه يحتاجه لنقاط الاستعادة التي
  يديرها الخادم؛ لا يُستخدم fallback ثابت.
- `BACKUP_SCHEDULER_PASSWORD` اختياري: عند غيابه يتوقف المجدول برسالة واضحة
  ولا يُنشئ كلمة مرور بديلة.
- مفتاح GitHub يحفظ في Replit Secrets أو مخزن أسرار مؤسسي، ولا يوضع في remote
  URL أو سجل الأوامر.

## الفحوص

```bash
pnpm security:scan
pnpm audit --prod --audit-level=high
```

يفشل فحص المستودع عند وجود private key أو token معروف أو ملف بيئة متتبع أو
بيانات الاتصال الشخصية التي يجب ألا تكون في السطح العام. فحص التبعيات يصنّف
النتيجة قبل اعتماد الإصدار ولا يستبدل مراجعة مالك الحزمة.

## الاستجابة

عند العثور على سر منشور: أوقف استخدامه، ألغِه ودوّره، حدّد الأثر، ثم وثّق
القرار قبل أي تنظيف للتاريخ. لا تُجرى إعادة كتابة لتاريخ `main` دون قرار
موثق ونسخة احتياطية واتفاق على أثر ذلك على النسخ المستنسخة.
