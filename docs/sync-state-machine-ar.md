# آلة حالات المزامنة

## 1. العقدة والاقتران

```text
محلية غير معروفة
  -> pairing code صادر
  -> pairing consumed
  -> trusted
  -> revoked
```

رمز الاقتران أحادي الاستخدام ومؤقت. يبقى سجل الثقة والإلغاء للتدقيق، ولا
تكفي معرفة `nodeId` لقبول حزمة.

## 2. outbox

```text
pending -> exported -> acknowledged
```

- `pending`: التغيير المحلي محفوظ ولم يدخل حزمة مؤكدة.
- `exported`: أُدرج في حزمة ذات `baseVector` و`lastVector`.
- `acknowledged`: أكد الطرف المستهدف استلام الحزمة وتطبيقها.

لا يحذف النظام التغيير عند `exported`؛ يمكن إعادة التصدير عند انقطاع النقل.

## 3. inbox

```text
received -> validated -> applied
                   ├-> duplicate
                   ├-> conflict
                   └-> rejected
```

التكرار لا يعد تعارضًا إذا تطابقت العملية والحمولة القانونية. الحزمة ذات
التسلسل الناقص تُرفض قبل تطبيقها. كل تغيير داخل SAVEPOINT كي لا يمنع تغيير
متعارض بقية الحزمة.

## 4. cursor والمتجهات

`cursor` هو آخر متجه معرفة موثق لكل نظير. لا يساوي عدد الصفوف في قاعدة محلية.
تحسب الحزمة من التغييرات التي تتجاوز `baseVector`، ويحفظ `lastVector` الناتج
مع الحزمة. عند إعادة التشغيل يعاد استخدام السجل الدائم بدل التخمين من الذاكرة.

## 5. tombstone

الحذف الناعم أو الصريح يولد tombstone بمعرّف الكيان وتغيير الحذف والعقدة
المصدر. يمنع tombstone عودة كيان محذوف عند وصول حزمة قديمة. لا تنظف tombstones
إلا بعد سياسة احتفاظ تثبت تقارب كل النظائر.

## 6. conflict

```text
open -> resolved(approve|reject|correct)
     -> deferred
```

القرار الإداري يكتب `resolvedBy` و`resolution` ووقت الحل. الرفض يستبعد
التغيير من الحزم التالية، والتصحيح يولد تغييرًا جديدًا قابلًا للنشر، والتأجيل
لا يعد نجاحًا ولا يزيل الحادثة من قائمة العمل.

## 7. الجلسة والحزمة

```text
created -> handshake -> prepared -> transferring -> completed
                                      └-> partially-applied
                                      └-> failed
created/handshake/prepared -> cancelled
```

كل حزمة مرتبطة بجلسة واتجاه ومصدر وهدف وبصمة. الإقرار لا يتم إلا من العقدة
المستهدفة، والجلسة لا تكتمل إلا بعد إقرار الحزم المطلوبة في الاتجاهين.
